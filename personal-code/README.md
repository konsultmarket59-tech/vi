# Личный код

Десктопное приложение для разработки: агент, который пишет код, и обычный редактор, чтобы
писать его руками. Работает через ваш аккаунт Polza — то есть через те же модели, что и
«Личный чат», — с переключателем прокси и работой с git-репозиторием.

Это второе приложение в этом репозитории. Первое — `personal-chat` («Личный чат»), рабочий
инструмент для агентства. `personal-code` — инструмент для разработки самого «Личного чата»
и любого другого проекта.

---

## Зачем оно отдельно

«Личный чат» — про маркетинг: проекты, тексты, дизайн, таблицы, отчётность. Смешивать с ним
разработку не нужно: у них разные пользователи (вы и разработчик), разный цикл обновлений и
разный набор рисков. Поэтому это отдельная программа со своим установщиком, но в том же
репозитории — чтобы код был в одном месте.

Что оно умеет:

- **Вайб-код.** Опишите задачу словами — агент прочитает нужные файлы и предложит правку.
- **Ручной код.** Полноценный редактор с подсветкой, автодополнением и поиском: разработчик
  работает в нём напрямую, без агента.
- **Git.** Изменения, дифф, индекс, коммиты, ветки, push/pull — из окна приложения.
- **Сборки.** Конфигурации кастомных версий «Личного чата»: какие разделы входят в конкретную
  сборку и как она называется.

---

## Установка

```
cd personal-code
npm install
npm run electron:build:win     # установщик для Windows в папке release/
```

Для разработки самого приложения: `npm run electron:dev`.

При первом запуске откроется вкладка **Настройки** — там нужно вставить ключ Polza.

---

## Настройки

**Модели.** Адрес API (`https://polza.ai/api/v1`), ключ, модель. Кнопка «Загрузить список»
подтягивает модели, доступные на вашем аккаунте. Температуру для кода лучше держать низкой
(0.1–0.3) — код не то место, где нужна фантазия.

**Прокси.** Три режима:

| Режим | Что делает |
|---|---|
| Системный | Берёт настройки прокси из Windows — работает вместе с обычным VPN-клиентом |
| Свой адрес | `http://хост:порт` или `socks5://хост:порт`, при необходимости с логином и паролем |
| Прямое соединение | Игнорирует системный прокси полностью |

Кнопка «Проверить соединение» бьёт в тот адрес API, который указан выше, — то есть проверяет
разом DNS, прокси, его пароль и ваш ключ, а не абстрактную доступность интернета.

**Git.** Имя и почта для коммитов. Токен нужен только если компьютер не помнит доступ к
GitHub; он передаётся git через переменную окружения, а не аргументом командной строки —
иначе его было бы видно в списке процессов.

Всё это хранится в папке настроек приложения на вашем компьютере и **никогда не попадает в
репозиторий**.

## Вкладка «Код»

Слева дерево файлов, посередине редактор, справа агент.

В дерево не попадают `node_modules`, `dist`, `.git`, `.venv` и подобные служебные папки — они
огромные и не редактируются вручную. Двоичные файлы видны, но не открываются как текст.

**Редактор** — CodeMirror: нумерация строк, подсветка синтаксиса (TypeScript, JavaScript,
Python, HTML, CSS, JSON, Markdown), автодополнение скобок, поиск по файлу, отмена. `Ctrl+S`
сохраняет. Пока файл не сохранён, рядом с именем горит точка.

### Как работает агент

Агент видит папку проекта и работает в два шага.

**Шаг 1 — читает.** Прежде чем что-то предлагать, он запрашивает файлы, ищет по проекту,
смотрит `git status`. Эти действия выполняются сразу и без подтверждения: они ничего не
меняют, спрашивать разрешения на каждое чтение было бы только помехой.

**Шаг 2 — предлагает.** Правка приходит как **дифф**: видно, какие строки уходят и какие
приходят. На диске в этот момент ничего не изменилось. Изменения записываются только после
нажатия «Применить». «Отклонить» — и файл остаётся прежним.

Так же устроены команды: если агент хочет запустить тесты или сборку, он показывает команду,
а запускаете её вы. Результат можно вернуть агенту кнопкой «Показать агенту» — тогда он
увидит, что упало, и предложит следующую правку.

Правки бывают четырёх видов: заменить фрагмент, записать файл целиком, удалить, переименовать.
Основной — замена фрагмента: агент обязан привести кусок существующего кода дословно, и если
такого куска в файле нет или он встречается несколько раз, правка отклоняется с объяснением, а
не применяется наугад.

**Границы.** Ни агент, ни интерфейс не могут прочитать или изменить файл за пределами открытой
папки: каждый путь проверяется, и попытка выйти наружу (`../../`) отклоняется. Проверка стоит
и на предпросмотре, и на записи.

**Переписка** ведётся отдельно для каждой папки: открыли другой проект — другой диалог, чужой
контекст не подмешивается.

## Вкладка «Git»

Всё поверх обычного `git`, установленного в системе (на Windows — Git for Windows).

Видно текущую ветку, отставание/опережение от сервера, список изменений с разделением на «в
коммите» и «не добавлено». По клику на файл открывается дифф. Дальше — добавить в коммит,
написать сообщение, закоммитить, отправить.

Разрушающие действия («Отменить изменения в файле», push) спрашивают подтверждение. Сообщение
коммита передаётся git как отдельный аргумент, а не через оболочку, поэтому кавычки, `$`,
точки с запятой в тексте сообщения остаются текстом.

Если в папке нет репозитория, предлагается его создать.

## Вкладка «Плагины»

Архив готовых дополнений к «Личному чату», который лежит у вас в «Документы\Личный код\Плагины».

Плагин — это именованный набор навыков и, если нужно, исходников модуля. Работает так: агент во
вкладке «Код» пишет плагин прямо в репозитории, а отсюда он забирается в архив — файлы навыков и
папки с кодом складываются в новую версию.

**Версии не перезаписываются.** Каждое сохранение — новая папка `v1`, `v2`, `v3` рядом со старыми.
«Обновить до новой версии» добавляет версию существующему плагину; «Сохранить отдельным плагином»
заводит новый, даже если название совпадает. Всегда можно вернуться к тому, что уже отдано
тестировщикам.

Исходники **копируются**, а не запоминаются ссылкой: через полгода версия должна открываться,
даже если файлы в репозитории давно переписаны.

«Выгрузить выбранное» кладёт навыки отмеченных версий в папку `bundled-skills` сборки «Личного
чата». Папка пересобирается целиком, поэтому убранный плагин действительно исчезает из следующей
сборки, а не остаётся от прошлого раза.

В приложении тестировщика такие навыки видны по названию, но их текст не передаётся в окно и не
редактируется. Навыки, которые тестировщик пишет сам, он видит целиком.

## Вкладка «Сборки»

Здесь описывается, из чего состоит конкретная версия «Личного чата».

База одинакова у всех и не отключается: чат с выбором модели, проекты и инструкции, навыки,
задачи по расписанию, файлы с компьютера, сохранение результатов и дизайн. Опционально
включаются Excel, Word, Медиа, Облако, Директ, GitHub, Боты. Кнопка «Выгрузить plugins.json» кладёт файл
конфигурации в папку исходников «Личного чата».

Дальше эта сборка собирается обычным `npm run electron:build:win` в папке `personal-chat` — и
получается приложение со своим названием и только нужными разделами. Никакого форка кода: одна
кодовая база, разные конфигурации.

Если `plugins.json` нет, включено всё — поэтому обычная сборка ничем не отличается от прежней.

## Вкладка «Демо-доступ»

Раздача демо-копий «Личного чата» тестовой группе: каждая копия привязана к одному
компьютеру, работает до указанной даты, и её можно отключить досрочно.

Это **не** продажа лицензий — это контроль над копиями, которые вы раздали сами. Юридическая
часть (правообладание, лицензионный договор) для продаж по-прежнему нужна отдельно и здесь не
затрагивается.

### Как это работает

Один раз создаётся **ключ подписи**. Закрытая половина остаётся на вашем компьютере, в папке
настроек «Личного кода», и никуда не уходит — ни в репозиторий, ни в сборку. В демо-сборку
попадает только открытая половина: она умеет проверять подпись, но не ставить её. Поэтому
файл активации может выдать только вы.

Дальше цикл такой:

1. Тестировщик запускает демо-сборку и видит **код своего компьютера** — 20 знаков.
2. Присылает его вам; вы заводите его в списке и нажимаете «Выдать доступ».
3. Получается файл `.lic` — подписанный, с именем, компьютером и датой окончания. Отправляете
   его любым способом, это обычный файл.
4. Тестировщик открывает файл в приложении. Всё.

**Срок действия — основная защита.** Копия перестаёт работать в назначенный день сама, даже
если компьютер вообще не выходит в интернет.

**Отзыв — быстрый путь.** Если нужно отключить кого-то раньше срока: отметьте «Отозвать»,
нажмите «Выгрузить список отзыва» и положите полученный `revoked.json` по постоянной ссылке
(подойдёт любой статический хостинг — объектное хранилище, обычный сайт). Приложение читает
этот файл раз в 12 часов. Ссылка указывается в «Настройках сборки» и записывается в сборку.

Если ссылки нет — всё работает, просто досрочно отозвать нельзя: только дата.

Список отзыва тоже подписан. Неподписанный или подписанный чужим ключом список игнорируется —
иначе любой, кто может подменить ответ по этой ссылке, отключил бы разом все копии. Если
ссылка недоступна, копия продолжает работать до конца срока: тестировщик в поезде не должен
терять доступ из-за плохой связи.

### Имя копии

При выдаче доступа задаётся название именно этой копии — «Личный чат Виктории», «Личный чат
Василия». Оно приходит в файле активации, поэтому сборка одна, а подписаны копии по-разному.

### Предустановленный ключ и расход

В «Настройках сборки» можно вписать ключ Polza для всей тестовой группы. Тогда в демо-сборке поле
ключа не показывается, а вместо него — раздел «Расход моделей»: какие модели использованы за
день, неделю, месяц, сколько токенов и на какую сумму. Цены задаются построчно:

```
anthropic/claude-sonnet-5 300 1500
openai/gpt-5 250 1000
```

Числа — за миллион токенов: сначала входящие, потом исходящие. Модель без цены показывается с
токенами, но без суммы, и общий итог тогда тоже не выводится — сумма, не учитывающая часть
расхода, вводила бы в заблуждение.

**Заведите для группы отдельный ключ с небольшим балансом.** Ключ лежит внутри приложения на
чужом компьютере; спрятанное поле — это про аккуратность, а не про стойкость. Возможность
отозвать такой ключ и есть настоящая защита.

Пустой ключ означает обычную сборку, где каждый вводит свой; при этом прежний
`managed-config.json` удаляется, чтобы старый ключ не уехал в новую сборку незаметно.

### Порядок действий, когда собираете демо

```
1. «Демо-доступ» → Создать ключ                     (один раз, навсегда)
2. «Демо-доступ» → Настройки сборки → название, ссылка на отзыв, ключ Polza, цены
3. «Демо-доступ» → Записать настройки в сборку      (licence-config.json + managed-config.json)
4. «Плагины» → выбрать версии → Выгрузить выбранное (bundled-skills/)
5. (по желанию) «Сборки» → набор модулей → plugins.json
6. cd personal-chat && npm run electron:build:win
```

Полученный установщик — уже демо: без файла активации он показывает экран активации вместо
приложения.

**Ключ подписи не пересоздавайте.** Все выданные файлы активации подписаны им; новый ключ
разом обесценит их все. Сделайте копию файла `demo-signing-key.json` в надёжном месте.

Ваша собственная сборка от этого не страдает: без `licence-config.json` проверки нет вообще, и
приложение никогда не потребует активации.

### Насколько это надёжно — честно

Проверка идёт внутри приложения, значит всё нужное для неё лежит на компьютере тестировщика.
Человек с техническими навыками может распаковать установщик и убрать проверку. Это защищает
от того, чтобы копию передали дальше или запустили на втором компьютере; от целенаправленного
взлома — нет, и ничто, работающее на чужой машине, от этого защитить не может.

Для группы из десяти известных вам людей этого достаточно. На этапе фокус-группы настоящая
защита не техническая: расписка о неразглашении и то, что вы знаете каждого лично.

### Про продажу лицензий

Механизм выдачи и отзыва теперь есть, но продавать по нему пока нельзя — не потому, что не
хватает кода, а потому, что нет юридической формы: правообладания, лицензионного договора
или EULA и субъекта, от чьего имени выдаются права. Когда это появится, техническая часть
уже готова.

## Проверки

```
npm run build                                       # типы + сборка
npx oxlint                                          # линтер
node electron/smoke-backend.cjs                     # файлы, git, разбор правок, диффы
node electron/smoke-plugin-archive.cjs              # версии плагинов и выгрузка в сборку
xvfb-run -a npx electron electron/smoke-app.cjs     # интерфейс целиком
xvfb-run -a npx electron electron/smoke-agent.cjs   # агент против поддельного сервера моделей
```

`smoke-backend` проверяет в том числе то, что не должно работать: выход за пределы папки,
двоичные файлы, несовпадающий и неуникальный фрагмент правки, сообщение коммита с символами
оболочки.

`smoke-agent` поднимает локальный OpenAI-совместимый сервер со сценарными ответами и проходит
весь путь: запрос → чтение файла → предложение → дифф → применение и отдельно отклонение. Живую
модель так не проверить — она каждый раз отвечает по-разному, — но всё, что написано здесь,
проверяется по-настоящему.

В `personal-chat` есть парные проверки:

```
xvfb-run -a npx electron electron/smoke-plugins.cjs  # что plugins.json реально меняет сборку
node electron/smoke-licence.cjs                      # выдача и отзыв демо-доступа
xvfb-run -a npx electron electron/smoke-gate.cjs     # экран активации и отчёт о проблеме
```

`smoke-licence` проверяет обе стороны сразу: лицензия подписывается кодом из `personal-code` и
проверяется кодом из `personal-chat`. Отдельно проверяется то, что должно **не** работать:
лицензия для другого компьютера, просроченная, с испорченной подписью, подписанная чужим
ключом, а также поддельный список отзыва — он не должен уметь никого отключить.

## Что где лежит

```
personal-code/
  electron/
    main.cjs           окно и IPC
    preload.cjs        единственный мост в интерфейс
    settings.cjs       настройки, прокси, обращения к моделям
    workspace.cjs      файлы проекта; здесь же проверка выхода за пределы папки
    git.cjs            обёртка над git CLI
    agent.cjs          инструменты агента, разбор правок, диффы
    blueprints.cjs     конфигурации сборок «Личного чата»
    demoAccess.cjs     ключ подписи, выдача и отзыв демо-доступа
    pluginArchive.cjs  архив плагинов с версиями
    netFetch.cjs       запросы через сетевой стек Electron (чтобы работал прокси)
  src/
    App.tsx            оболочка и вкладки
    components/        дерево, редактор, агент, git, сборки, настройки
    lib/types.ts       типы и описание window.api
```
