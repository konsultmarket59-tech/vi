# «Личный код» — состояние работы и как продолжить

Этот файл нужен, чтобы разговор о приложении для разработки можно было продолжить
в другой ветке или в новой сессии, ничего не восстанавливая по памяти. Здесь —
что уже сделано, какие решения приняты и почему, что осталось.

Ветка, в которой всё лежит: `claude/personal-claude-chat-docs-untwa4`.
Репозиторий: `konsultmarket59-tech/vi`. Коммиты: `ff38845`, `c5aa067`, `1736248`.

## Что это за приложение

`personal-code` — отдельное десктопное приложение (Electron) в том же репозитории,
что и `personal-chat` («Личный чат»). Два разных продукта:

- **«Личный чат»** — рабочий инструмент агентства (маркетинг, тексты, таблицы, дизайн).
  Им пользуется владелица и, на этапе тестирования, фокус-группа.
- **«Личный код»** — инструмент разработки: им ведётся разработка самого «Личного
  чата» и им же готовятся сборки для тестовой группы. Пользуется владелица и
  разработчик.

Почему отдельно, а не разделом внутри чата: разные пользователи, разный цикл
обновлений, разный набор рисков. Код общий (один репозиторий), приложения — разные.

## Что уже работает

### Вкладка «Код»

Дерево файлов слева, редактор CodeMirror посередине, агент справа.

- **Вайб-код.** Агент сначала читает файлы (`READ`, `LIST`, `SEARCH`, `GIT`) — эти
  инструменты выполняются сразу, без подтверждения, потому что ничего не меняют.
  Потом предлагает правку **диффом**; на диске ничего не меняется, пока человек не
  нажмёт «Применить».
- **Ручной код.** Полноценный редактор: подсветка (TS/JS/Python/HTML/CSS/JSON/MD),
  автодополнение, поиск, `Ctrl+S`.
- **Команды** (тесты, сборка) агент только предлагает; результат можно вернуть ему
  кнопкой «Показать агенту».
- **Правки**: `replace` (основной — фрагмент должен совпадать дословно и быть
  уникальным, иначе отказ с объяснением), `write`, `delete`, `rename`.
- **Граница безопасности** — одна функция `workspace.resolveInside()`: ни агент, ни
  интерфейс не могут выйти за пределы открытой папки. Проверка стоит и на
  предпросмотре, и на записи (это отдельно чинилось — сначала стояла только на записи).
- Переписка агента хранится **отдельно для каждой папки**.

### Вкладка «Git»

Поверх системного `git` через `execFile` с массивом аргументов (не через оболочку —
поэтому кавычки и `$` в сообщении коммита остаются текстом). Статус, дифф, индекс,
коммиты, ветки, push/pull/fetch. Разрушающие действия подтверждаются. Токен для push
передаётся через переменную окружения, а не аргументом (иначе виден в списке процессов).

### Вкладка «Сборки»

Конфигурации кастомных версий «Личного чата» → `plugins.json` в папке исходников чата.

**База не отключается** (решение владелицы): чат с выбором модели, проекты и
инструкции, навыки, задачи по расписанию, файлы с компьютера, сохранение
результатов, дизайн. Опционально: Excel, Word, Медиа, Облако, Директ, GitHub, Боты.

### Вкладка «Плагины»

Архив в «Документы\Личный код\Плагины». Плагин = навыки + (необязательно) исходники
модуля, с нумерованными версиями `v1`, `v2`, …

- «Обновить до новой версии» — версия рядом со старой, старая остаётся.
- «Сохранить отдельным плагином» — новый плагин, даже при том же названии.
- Исходники **копируются**, а не запоминаются ссылкой.
- «Выгрузить выбранное» пересобирает `bundled-skills/` в сборке чата **целиком**,
  поэтому убранный плагин действительно исчезает.

### Вкладка «Демо-доступ»

Выдача и отключение демо-копий «Личного чата».

- Ed25519-ключ подписи создаётся один раз, закрытая половина не покидает компьютер.
- Файл активации `.lic` привязан к компьютеру (20 hex-знаков из машинного идентификатора)
  и к дате окончания.
- **Срок — основная защита**: копия умирает сама, даже без интернета.
- **Отзыв — быстрый путь**: подписанный `revoked.json` по постоянной ссылке,
  читается раз в 12 часов. Неподписанный или чужой список игнорируется; недоступная
  ссылка не выключает копию.
- Имя копии («Личный чат Марии») приходит в лицензии — сборка одна, подписи разные.
- Ключ Polza для группы и таблица цен пишутся в `managed-config.json` сборки.

## Что сделано в «Личном чате» ради этого

- `licence.cjs` — проверка активации. **Без `licence-config.json` проверки нет вообще**,
  поэтому собственную копию владелицы заблокировать невозможно.
- `managed.cjs` — предустановленный ключ; в настройках поле ключа скрыто, вместо него
  расход.
- `usage.cjs` — расход по моделям за день/неделю/месяц. Точный, если сервис вернул
  `usage`; иначе оценка по длине, **явно помеченная**. Модель без заданной цены — без
  выдуманной суммы, и общий итог тогда не показывается.
- `bundledSkills.cjs` — навыки автора: видно название и описание, текст вырезается на
  границе main↔renderer и в окно не попадает.
- `report.cjs` — отчёт о проблеме файлом на рабочий стол; ничего не отправляется само.
- `plugins.cjs` — какие модули входят в сборку.

## Принятые решения, которые не надо пересматривать заново

1. **Лицензирование как продажа — не делаем.** Механизм выдачи/отзыва есть, но продавать
   по нему нельзя, пока нет юридической формы: правообладания, лицензионного договора
   или EULA и субъекта, от чьего имени выдаются права. Это решение владелицы.
2. **Защита клиентская и это признано честно.** Ключ, тексты навыков и проверка лицензии
   физически лежат на компьютере тестировщика. Защищает от передачи копии и запуска на
   втором компьютере, не защищает от того, кто распакует установщик. Отсюда требование:
   **для группы — отдельный ключ Polza с небольшим балансом**, который не жалко отозвать.
3. **Никаких секретов в репозитории.** В git идёт только исходный код. В `.gitignore`:
   `plugins.json`, `licence-config.json`, `managed-config.json`, `bundled-skills/`.
   Личные данные, токены и ключи — только в папках приложения на компьютере.
4. **Propose-then-confirm** для всего, что меняет данные. Читающие операции — сразу.
5. **Цифры не выдумываются.** Если цена модели не задана — показываются токены без суммы.
   Если расход оценочный — так и написано.

## Что осталось / обсуждалось, но не сделано

- **Автообновление.** Обсуждали `electron-updater` с обычного статического адреса (там же,
  где список отзыва). Не сделано: нужен адрес, который контролирует владелица. Пока
  обновление = собрать установщик и переустановить.
- **Живая проверка Polza.** Из среды разработки нет интернета: и агент, и учёт расхода
  проверены на локальном поддельном OpenAI-совместимом сервере. Как именно отвечает Polza
  (возвращает ли `usage`, принимает ли `stream_options`), выяснится на первом живом запросе.
- **Реальный отзыв через хостинг** — проверен на локальном сервере, не на настоящей ссылке.
- **Выдача лицензионных ключей для продаж** — см. решение 1.

## Как проверять

```
cd personal-code
npm run build                                        # типы + сборка
npx oxlint                                           # линтер
node electron/smoke-backend.cjs                      # файлы, git, разбор правок, диффы
node electron/smoke-plugin-archive.cjs               # версии плагинов и выгрузка
xvfb-run -a npx electron electron/smoke-app.cjs      # весь интерфейс
xvfb-run -a npx electron electron/smoke-agent.cjs    # агент против поддельного сервера

cd ../personal-chat
node electron/smoke-licence.cjs                      # выдача, отзыв, срок, подделки
node electron/smoke-managed.cjs                      # ключ в сборке, учёт, скрытие навыков
xvfb-run -a npx electron electron/smoke-plugins.cjs  # plugins.json меняет сборку
xvfb-run -a npx electron electron/smoke-gate.cjs     # активация, имя копии, расход, навыки
```

Тесты проверяют не только то, что работает, но и то, что **не должно** работать: выход за
пределы папки, лицензию для другого компьютера, просроченную, с чужой подписью, поддельный
список отзыва, попытку изменить предустановленный навык.

Ветка та же (`claude/personal-claude-chat-docs-untwa4`) или новая от неё.
