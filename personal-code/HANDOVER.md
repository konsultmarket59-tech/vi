# «Личный код» — состояние работы и как продолжить

Этот файл нужен, чтобы разговор о приложении для разработки можно было продолжить
в другой ветке или в новой сессии, ничего не восстанавливая по памяти. Здесь —
что уже сделано, какие решения приняты и почему, что осталось.

Работа началась в ветке `claude/personal-claude-chat-docs-untwa4` и продолжается
в `claude/personal-code-status-4ov1c9`, отведённой от неё и один раз слитой заново
с каноническим кодом (коммит слияния `c38c98d`), когда та ветка ушла вперёд на
Документооборот, Визуализацию, Финмодель, Клининг и кэш промпта.
Репозиторий: `konsultmarket59-tech/vi`.

---

## Что это за приложение

`personal-code` — отдельное десктопное приложение (Electron) в том же репозитории,
что и `personal-chat` («Личный чат»). Два разных продукта:

- **«Личный чат»** — рабочий инструмент агентства (маркетинг, тексты, таблицы).
  Им пользуется владелица и, на этапе тестирования, фокус-группа.
- **«Личный код»** — инструмент разработки: им ведётся разработка самого «Личного
  чата» и им же готовятся сборки для тестовой группы. Пользуется владелица и
  разработчик.

Почему отдельно, а не разделом внутри чата: разные пользователи, разный цикл
обновлений, разный набор рисков. Код общий (один репозиторий), приложения — разные.

## Что уже работает

### Вкладка «Код»

Дерево файлов слева, редактор CodeMirror посередине, агент справа.

- **Вайб-код.** Агент сначала читает файлы (`READ`, `LIST`, `SEARCH`, `GIT`) — эти
  инструменты выполняются сразу, без подтверждения, потому что ничего не меняют.
  Потом предлагает правку **диффом**; на диске ничего не меняется, пока человек не
  нажмёт «Применить».
- **Ручной код.** Полноценный редактор: подсветка (TS/JS/Python/HTML/CSS/JSON/MD),
  автодополнение, поиск, `Ctrl+S`.
- **Команды** (тесты, сборка) агент только предлагает; результат можно вернуть ему
  кнопкой «Показать агенту».
- **Правки**: `replace` (основной — фрагмент должен совпадать дословно и быть
  уникальным, иначе отказ с объяснением), `write`, `delete`, `rename`. Перед записью
  файлы сверяются с тем, какими их показывал дифф: если файл успели изменить, правка
  не применяется целиком, а не наполовину.
- **Граница безопасности** — одна функция `workspace.resolveInside()`: ни агент, ни
  интерфейс не могут выйти за пределы открытой папки. Проверка стоит и на
  предпросмотре, и на записи (это отдельно чинилось — сначала стояла только на записи),
  и отдельно проверяется символическая ссылка изнутри папки наружу: путь остаётся
  внутри, а открывалось то, на что ссылка показывает.
- Переписка агента хранится **отдельно для каждой папки**.
- Настройки те же, что в чате: папка с данными, доступ в интернет (поиск и чтение
  страниц — читающие инструменты, выполняются сразу), обслуживание («что занимает
  место»).

### Вкладка «Git»

Поверх системного `git` через `execFile` с массивом аргументов (не через оболочку —
поэтому кавычки и `$` в сообщении коммита остаются текстом). Статус, дифф, индекс,
коммиты, ветки, push/pull/fetch. Разрушающие действия подтверждаются. Токен для push
передаётся через переменную окружения, а не аргументом (иначе виден в списке процессов).

### Вкладки «Демо» и «Чистовая сборка» — устройство переделано целиком

Раньше сборка, тестировщик и репозиторий на GitHub были тремя разными вещами,
заводились порознь и расходились. Теперь это одна сущность — **копия**
(`electron/copies.cjs`), и обе вкладки — один и тот же компонент `CopiesView`,
различающийся только `kind: "demo" | "paid"`:

- `demo` — ключ Polza вшит автором и скрыт от человека, срок ограничен.
- `paid` — человек вводит и видит свой ключ; привязка к компьютеру остаётся
  «защитой от копирования», если её явно не снять — это не переключатель
  «оплачено/не оплачено», это отдельная договорённость.

Копия хранит: кому (имя → название в окне и имя репозитория выводятся сами),
конфигурацию (база всегда; Excel/Word и восемь плагинов — Документооборот,
Визуализация, Финмодель, Клининг, Медиа, Облако, Директ, Чат-боты — отмечаются),
доступ к моделям, срок и привязку к компьютеру, репозиторий, и — важно —
**историю отозванных лицензий** прямо в записи копии (`revokedLicenceIds`), а не
выводит её из одного триггера `revoked`, поэтому перевыдача после отзыва не
возвращает старую копию к жизни (тот же класс бага, что раньше чинился в
`demoAccess.cjs`, — здесь пришлось повторить осознанно, отдельным тестом).

Оплаченная копия может **продолжить жить в репозитории своей демо-копии**
(`fromCopyId`) — это единственное легитимное совпадение `repoName` у двух разных
`id`, и `copies.save()` отдельно отличает его от настоящего столкновения имён.

Кнопка «Собрать» теперь не запускает `npm run electron:build:win` локально —
это делает `electron/publish.cjs`: снимок папки `personal-chat` из канонической
ветки **одним коммитом без истории монорепозитория** → закрытый репозиторий на
GitHub (создаётся или переиспользуется) → туда push force → в репозиторий
дописываются `plugins.json`/`managed-config.json`/`licence-config.json` и файл
рабочего процесса → сборка запускается на GitHub Actions. Каждый шаг — строка в
окно по мере выполнения (`copies:publishLog`), потому что это минуты, а не секунды.

`electron/build.cjs` (локальная сборка) никуда не делась — им пользуются тесты
и он остался бы нужен, если понадобится собирать без GitHub, — но кнопка в
интерфейсе на него больше не ведёт.

Ключ подписи демо-доступа создаётся прямо на вкладке «Демо» (раньше жил в
отдельной вкладке «Демо-доступ», которая была удалена целиком вместе со старой
«Сборки» — оба экрана `BlueprintsView.tsx`/`DemoAccessView.tsx` больше не
существуют, IPC под них вычищен, кроме `demo:keyInfo`/`demo:createKeys` и
`blueprints:pickSource`, которые всё ещё используются).

### Вкладка «Плагины» — без изменений в этой сессии

Архив в «Документы\Личный код\Плагины». Плагин = навыки + (необязательно) исходники
модуля, с нумерованными версиями `v1`, `v2`, …

- «Обновить до новой версии» — версия рядом со старой, старая остаётся.
- «Сохранить отдельным плагином» — новый плагин, даже при том же названии.
- Исходники **копируются**, а не запоминаются ссылкой.
- «Выгрузить выбранное» пересобирает `bundled-skills/` в сборке чата **целиком**,
  поэтому убранный плагин действительно исчезает.
- У плагина записана **ветка репозитория**, в которой живёт его код, а у каждой
  версии — коммит, из которого она взята. Новая версия наследует ветку плагина, а
  не берёт текущую. «Открыть ветку плагина» переводит открытую папку на неё;
  слияние остаётся ручным действием во вкладке «Git».

### Вкладка «Фикс» — новая

Чинить копию, которая уже у тестировщика: выбираете копию, подгружаете файл
отчёта о проблеме или пишете своими словами, «Отдать агенту» — репозиторий
именно этой копии клонируется (или подтягивается, если уже клонирован) в папку
с данными и открывается как рабочая папка вкладки «Код». Дальше обычный цикл:
агент читает код, предлагает правку диффом, подтверждение, коммит и push во
вкладке «Git» — ничего специального для копий там нет, это тот же редактор.

## Что сделано в «Личном чате» ради этого

- `licence.cjs` — проверка активации. **Без `licence-config.json` проверки нет вообще**,
  поэтому собственную копию владелицы заблокировать невозможно.
- `managed.cjs` — предустановленный ключ; в настройках поле ключа скрыто, вместо него
  расход.
- `usage.cjs` — расход по моделям за день/неделю/месяц. Точный, если сервис вернул
  `usage`; иначе оценка по длине, **явно помеченная**. Модель без заданной цены — без
  выдуманной суммы, и общий итог тогда не показывается.
- `bundledSkills.cjs` — навыки автора: видно название и описание, текст вырезается на
  границе main↔renderer и в окно не попадает.
- `report.cjs` — отчёт о проблеме файлом на рабочий стол; ничего не отправляется само.
  **Теперь общий модуль**: скопирован дословно в `personal-code/electron/report.cjs`, у
  «Личного кода» тоже есть «О программе и отчёт о проблеме» в настройках.
- `github.cjs` — тоже стал общим: `personal-code/electron/github.cjs` — та же копия, и на
  ней целиком стоит публикация копий в `publish.cjs` (создание репозитория, push, коммиты
  файлов конфигурации, запуск workflow).
- `plugins.cjs` — какие модули входят в сборку.
- Экран активации: условие копии («не для продажи, не передаётся, сообщите код
  разработчику») на каждом экране шлюза, а на истёкшем сроке — прямое обещание,
  что проекты и документы остались на месте и продление подхватит их даже спустя
  время. Это проверяется тестом, а не только написано.

Каноническая ветка (`claude/personal-claude-chat-docs-untwa4`) с тех пор ушла вперёд ещё на
несколько модулей — Документооборот, Визуализацию, Финмодель, Клининг, — они пришли в эту
ветку слиянием (`c38c98d`) и не описаны здесь подробно: искать их устройство в самом коде
или в истории коммитов канонической ветки, этот файл её не дублирует.

Отдельно от демо-доступа, но в той же ветке (`75abdd5`) — задержка перед началом ответа.
Причина измерена, а не угадана: на проекте из пяти документов системный промпт занимал
206k символов (~69k токенов) и пересылался целиком с каждым сообщением.

- У каждого документа проекта есть галочка «отдавать ассистенту». Снятая — документ
  остаётся в проекте, но уходит из того, что шлётся на каждое сообщение. Рядом с «Что
  видит ассистент» появляется подсказка, когда промпт переваливает за ~90k символов.
- Извлечение текста из `.docx`/`.pdf`/`.xlsx` кэшируется по пути, времени изменения и
  размеру: раньше файлы разбирались заново на каждую пересборку промпта, 123 мс → 8 мс.
- Картинки чата кэшируются в окне, а не перечитываются и не кодируются в base64 заново
  на каждый ответ.

## Принятые решения, которые не надо пересматривать заново

1. **Лицензирование как продажа — не делаем.** Механизм выдачи/отзыва есть, но продавать
   по нему нельзя, пока нет юридической формы: правообладания, лицензионного договора
   или EULA и субъекта, от чьего имени выдаются права. Это решение владелицы.
2. **Защита клиентская и это признано честно.** Ключ, тексты навыков и проверка лицензии
   физически лежат на компьютере тестировщика. Защищает от передачи копии и запуска на
   втором компьютере, не защищает от того, кто распакует установщик. Отсюда требование:
   **для группы — отдельный ключ Polza с небольшим балансом**, который не жалко отозвать.
3. **Никаких секретов в репозитории.** В git идёт только исходный код. В `.gitignore`:
   `plugins.json`, `licence-config.json`, `managed-config.json`, `bundled-skills/`.
   Личные данные, токены и ключи — только в папках приложения на компьютере.
4. **Propose-then-confirm** для всего, что меняет данные. Читающие операции — сразу.
5. **Цифры не выдумываются.** Если цена модели не задана — показываются токены без суммы.
   Если расход оценочный — так и написано.
6. **Копия — одна сущность, не три.** Сборка, тестировщик и репозиторий больше не заводятся
   по отдельности (`electron/copies.cjs`): решение сделано, чтобы имя, конфигурация и
   репозиторий физически не могли разойтись, как расходились раньше. Не откатывать назад
   к отдельным вкладкам «Сборки» + «Демо-доступ», даже если понадобится что-то в них
   доработать — дорабатывать `CopiesView`/`copies.cjs`.
7. **Репозиторий копии — снимок, не форк.** `publish.cjs` пушит папку `personal-chat` одним
   коммитом без истории монорепозитория и без «Личного кода» рядом. Так и должно быть:
   в репозитории тестировщика не место истории агентства и коду разработки.

## Что осталось / обсуждалось, но не сделано

- **Автообновление.** Обсуждали `electron-updater` с обычного статического адреса (там же,
  где список отзыва). Не сделано: нужен адрес, который контролирует владелица. Пока
  обновление = собрать установщик и переустановить.
- **Живая проверка Polza и GitHub.** Из среды разработки нет интернета: агент, учёт расхода,
  доступ в интернет и весь конвейер `publish.cjs` (создание репозитория, push, запуск сборки)
  проверены на локальном поддельном OpenAI-совместимом сервере и юнит-тестами на `copies.cjs` —
  **ни разу не против настоящего GitHub API**. Первый реальный запуск «Собрать» на вкладке
  «Демо» — это первая проверка того, что `github.cjs` (перенесённый из чата без изменений)
  действительно создаёт репозиторий, пушит снимок и триггерит workflow_dispatch так, как
  задумано. Токен нужен с правами `repo` и `workflow` — поле в «Настройки → Git и GitHub»
  это уже проверяет через `testConnection` перед сохранением, но сама публикация — нет.
- **Реальный отзыв через хостинг** — проверен на локальном сервере, не на настоящей ссылке.
- **Рабочий процесс сборки, который пишет `publish.cjs` в репозиторий копии** —
  `.github/workflows/build.yml` внутри `workflow.yaml(displayName)` — не запускался ни разу
  на настоящем GitHub Actions runner'е Windows. Логика (npm ci → electron:build:win →
  softprops/action-gh-release) списана с уже работающего `build_personal_chat.yml` в корне
  монорепозитория, но сама генерация файла не тестировалась сборкой на реальном раннере.
- **Перенос отдельных версий/навыков между копиями (не всей конфигурации сразу)** — сейчас
  «Взять репозиторий у демо-копии» переносит весь набор плагинов и офисных модулей целиком;
  точечный перенос одного плагина в существующую оплаченную копию не сделан.
- **Выдача лицензионных ключей для продаж** — см. решение 1.

## Как проверять

```
cd personal-code
npm run build                                        # типы + сборка
npx oxlint                                           # линтер
node electron/smoke-backend.cjs                      # файлы, git, правки, сборка, копии, лицензии
node electron/smoke-plugin-archive.cjs               # версии плагинов, ветка, выгрузка
xvfb-run -a npx electron electron/smoke-app.cjs      # весь интерфейс
xvfb-run -a npx electron electron/smoke-agent.cjs    # агент против поддельного сервера

cd ../personal-chat
node electron/smoke-licence.cjs                      # выдача, отзыв, срок, подделки
node electron/smoke-managed.cjs                      # ключ в сборке, учёт, скрытие навыков
xvfb-run -a npx electron electron/smoke-plugins.cjs  # plugins.json меняет сборку
xvfb-run -a npx electron electron/smoke-gate.cjs     # активация, имя копии, расход, навыки
xvfb-run -a npx electron electron/bench-chat.cjs     # размер промпта, кэши, галочка документа
```

Тесты проверяют не только то, что работает, но и то, что **не должно** работать: выход за
пределы папки, лицензию для другого компьютера, просроченную, с чужой подписью, поддельный
список отзыва, попытку изменить предустановленный навык.

`bench-chat.cjs` — замер, который работает и тестом: он падает, если кэши перестали
работать или галочка перестала влиять на промпт.

## Как продолжить разговор в новой ветке

Дать новой сессии этот файл и `personal-code/README.md`. В README — подробное описание
каждой вкладки и порядок сборки демо; здесь — состояние, решения и незакрытые вопросы.
Ветка та же (`claude/personal-code-status-4ov1c9`) или новая от неё.

Самое вероятное первое действие следующей сессии — не код, а живой прогон: создать
демо-копию на вкладке «Демо» и нажать «Собрать» на настоящем компьютере с интернетом.
Всё, что описано выше про `publish.cjs`/`github.cjs`, проверено юнит-тестами и на локальном
поддельном сервере, но ни разу — против настоящего GitHub API. Первый живой прогон — это
и есть самая полезная работа, которую можно сделать дальше.
