# Личный чат

Персональное десктопное приложение: Claude-подобный чат с проектами (своя
инструкция + свои документы, как в Claude.ai), библиотекой навыков
(копирайтинг, делопроизводство и т.д.) и конструктором навыков с помощью ИИ.
Подключается к любой OpenAI-совместимой модели через
[Polza.ai](https://polza.ai) — своим API-ключом.

**Все данные — проекты, документы, чаты, навыки — хранятся обычными файлами
и папками прямо на вашем компьютере**, не в облаке и не в этом репозитории.
В репозитории — только программа.

## Установка (для пользователя — просто скачать и запустить)

Готовый файл для Windows собирается из этого проекта (см. раздел «Сборка»
ниже) и не требует установки — скачайте `.exe` и запустите двойным кликом.
При первом запуске Windows SmartScreen может показать предупреждение
«Windows защитила ваш компьютер» (потому что файл не подписан цифровой
подписью) — нажмите «Подробнее» → «Выполнить в любом случае».

## Как это устроено

При первом запуске приложение создаёт папку `Личный чат` в разделе
«Документы» на компьютере (её можно сменить в Настройках). Внутри:

```
Личный чат/
  projects/
    <название-проекта>/
      project.json      — инструкция, описание, подключённые навыки
      docs/              — обычные файлы: перетащите сюда .docx/.txt/.md,
                            приложение подхватит их автоматически
      chats/              — история переписки по проекту
  skills/
    <название-навыка>.json
```

Кнопка «📁 Открыть папку проекта» в приложении открывает эту папку в
проводнике — можно работать с документами и через приложение, и напрямую
через файловую систему.

## Настройка подключения к модели

1. Раздел **⚙️ Настройки**.
2. Base URL по умолчанию — `https://polza.ai/api/v1` (OpenAI-совместимый
   эндпоинт Polza.ai). Можно указать любой другой совместимый сервис.
3. Вставьте свой API-ключ Polza.ai.
4. Укажите модель — поле «Модель» подгружает список моделей прямо с Polza.ai
   (кнопка «Обновить список», или начните печатать — появятся варианты).
   Список ничем не ограничен приложением: доступна **любая модель, какая
   включена на вашем аккаунте Polza.ai** — ID можно и вставить вручную, если
   не нашли в подсказках (например только что активировали новую).
5. Сохраните.

Ключ хранится только локально на компьютере (в системной папке настроек
приложения), никуда, кроме указанного адреса API, не отправляется.

## Проекты

- **Инструкции** — системный промпт: роль ассистента, стиль, правила.
- **Документы** — файлы в папке `docs/` проекта. Распознаются автоматически:
  Word (`.docx`), старый Word (`.doc`), Excel (`.xlsx`), PDF (текстовый слой),
  `.txt`, `.md`, `.csv`, `.json`, `.rtf` (упрощённое извлечение). Старый
  формат `.xls` и отсканированные PDF без текстового слоя не читаются —
  пересохраните файл как `.xlsx`/текстовый PDF или вставьте текст вручную.
- **Папка на компьютере** — вместо копирования файлов в проект можно один раз
  указать существующую папку на вашем компьютере (вкладка «Документы» →
  «Папка на компьютере»). Файлы из неё не копируются и никуда не
  перемещаются — ассистент читает их прямо оттуда при каждом обращении к
  проекту, так что изменения в исходных файлах подхватываются автоматически.
  Поддерживаются те же форматы, что и для обычных документов.
- **Навыки** — подключаются из общей библиотеки.
- Несколько независимых чатов внутри проекта, история сохраняется как файлы.
- **Экспорт в PDF/PNG** — под каждым сообщением в чате (и над списком
  сообщений — для всего чата целиком) есть ссылки «Экспорт в PDF» / «Экспорт
  в PNG». Открывается системный диалог сохранения, по умолчанию — прямо в
  папку `docs/` текущего проекта, так что готовый документ сразу становится
  частью базы знаний проекта.
- **Дизайн (фирменный стиль)** — вкладка проекта «Дизайн»: название бренда,
  слоган, акцентный цвет, логотип, текст подвала (реквизиты/контакты). Всё
  это автоматически применяется и к экспорту в PDF/PNG (шапка с логотипом,
  акцентный цвет в заголовках/таблицах, подвал), и к графикам/оформлению
  прямо в чате этого проекта — так документы, которые готовит ассистент,
  сразу выглядят фирменно, без ручного форматирования.
  Дополнительно можно загрузить **QR-код** и указать **телефон/e-mail**: если
  QR-код загружен, шапка документа перестраивается в три зоны — логотип
  слева, название и слоган по центру, а телефон и e-mail (если заполнены) и
  QR-код — справа, с одинаковым отступом от края. Без QR-кода шапка остаётся
  в простом виде (логотип + название/слоган слева).
  Есть и третий вариант — **загрузить готовую шапку целиком одной картинкой**
  (кнопка «Загрузить готовую шапку целиком»): тогда она используется как
  есть, поля выше на саму шапку не влияют (акцентный цвет и подвал документа
  продолжают применяться).
- **Визуализация данных** — ассистент может строить настоящие графики
  (столбчатые, линейные, круговые) прямо в ответе — просто попросите
  визуализировать данные. Графики рендерятся как SVG (не как картинка с
  сервера) и попадают как в живой чат, так и в экспортированные PDF/PNG.

### Перенос своих проектов из Claude.ai

Кнопка **«Импорт из Claude.ai (.json)»** в боковой панели принимает файлы
экспорта проектов Claude.ai в исходном формате (`name`, `description`,
`prompt_template`, `docs[]`) — так переносятся инструкции и документы в
локальный проект (файлы документов создаются прямо в папке `docs/`).

## Навыки и конструктор навыков

Раздел **🧩 Навыки** — общая библиотека переиспользуемых инструкций.
Подключается к нужным проектам на вкладке проекта «Навыки».

Кнопка **«✨ Создать навык с помощью ИИ»** открывает диалог: опишите задачу,
ассистент задаст уточняющие вопросы и предложит готовый навык — нажмите
«Сохранить как новый навык».

Готовые навыки можно **импортировать** — как в Claude:
- **«Загрузить из файла (.md)»** — файл с YAML-заголовком (`name:`,
  `description:`) и текстом инструкции после него; если заголовка нет, имя
  берётся из названия файла, а весь текст становится инструкцией.
- **«Загрузить из папки (SKILL.md)»** — папка с файлом `SKILL.md` (тот же
  формат заголовка) и, при необходимости, дополнительными материалами рядом
  (`.txt`, `.docx`, `.xlsx`, `.pdf` и т.д.) — их текст автоматически
  подставляется в навык вслед за основной инструкцией.

В обоих случаях импортированный навык открывается в редакторе для проверки —
ничего не сохраняется автоматически, пока вы не нажмёте «Сохранить навык».

## 💼 Операционка

Раздел, куда переносится финансовая/операционная модель агентства (ставки
команды, расходы, экономика по клиентам, платежи, библиотека процессов,
прогноз) — как в присланном вами `dinamika_ops_full.xlsx`.

- **«Импортировать xlsx»** — выберите любой `.xlsx`, каждый лист станет
  отдельной редактируемой таблицей (данные, не формулы — формулы Excel не
  пересчитываются внутри приложения, это снапшот-таблица для быстрых
  правок и вопросов, а не замена Excel). Повторный импорт файла с теми же
  названиями листов обновляет их, не создавая дублей.
- Таблицы редактируются прямо в интерфейсе (ячейки, добавление/удаление
  строк), сохраняются как обычные JSON-файлы в `operations/`.
- **«🤖 Агент операционки»** — отдельный чат, которому видно текущее
  состояние всех листов. Спросите что угодно по цифрам, или попросите
  добавить/изменить/удалить запись — агент предложит точное изменение
  (лист, действие, значения), которое нужно подтвердить кнопкой
  «Применить» — без подтверждения ничего не меняется.
- Раздел оформлен как отдельное окно-приложение внутри интерфейса: листы —
  это вкладки сверху (как в Excel), первая строка таблицы закреплена как
  заголовок при прокрутке, левый столбец с номером строки тоже закреплён —
  удобно работать с широкими и длинными таблицами, не теряя ориентацию.

## 🎨 Медиа

Генерация изображений, видео и аудио через единый Media API Polza.ai —
использует тот же ключ, что уже настроен для чата, отдельная подписка не
нужна. Модели (фото/видео/звук) подключаются по ID — какие именно доступны
и сколько стоят, смотрите на [polza.ai/models](https://polza.ai/models).

- Раздел **🎨 Медиа**: тип (изображение/видео/аудио), ID модели, промпт,
  необязательное референс-изображение (для image-to-image/video), сложные
  параметры конкретной модели (`duration`, `aspect_ratio` и т.п.) — через
  поле «дополнительные параметры (JSON)», по желанию — привязка к проекту
  (тогда результат сохраняется в его `media/`, иначе — в общую `media/` в
  папке данных). Справа — история генераций с превью.
- **Прямо в чате проекта**: попросите ассистента что-то нарисовать/озвучить
  — он предложит генерацию тем же способом, что и с графиками/операционкой
  (карточка с моделью и промптом + кнопка «Сгенерировать»/«Отклонить»).
  Ничего не создаётся без явного нажатия — как и с отправкой писем, генерация
  (а значит и её стоимость) — только по вашему подтверждению.
- Генерация асинхронная: приложение опрашивает Polza раз в несколько секунд
  до готовности (картинки — обычно до 2 минут, видео — до 10 минут), готовый
  файл скачивается и сохраняется локально; сам процесс отменить нельзя, но
  можно просто закрыть карточку и не ждать результата.

## 🖌️ Дизайн

Раздел для статичных дизайн-материалов: посты, макеты документов, слайды
презентаций, дизайн-системы, черновики страниц сайта, простая векторная
графика (логотипы, иконки) — с мультиформатным экспортом.

1. **«✨ Создать дизайн»** открывает чат с дизайн-ассистентом: опишите
   задачу («квадратный пост для ВКонтакте с анонсом акции», «слайд
   презентации с тремя тезисами», «иконка календаря в векторе») — ассистент
   предлагает готовый вариант карточкой с живым предпросмотром, нажмите
   «Сохранить», чтобы добавить в галерею (ничего не сохраняется без этого
   нажатия). По желанию можно привязать раздел к конкретному проекту
   (выпадающий список сверху) — тогда ассистенту виден фирменный стиль
   проекта (акцентный цвет, название) и он старается выдержать его в
   дизайне.
2. **Галерея** — все сохранённые дизайны с превью; клик открывает просмотр
   и кнопки экспорта.
3. **Экспорт**: обычные дизайны (посты, документы, презентации, сайты,
   дизайн-системы) — в **PNG / JPG / PDF**. Векторная графика (логотипы,
   иконки) — дополнительно в **SVG** как есть, без растеризации.
4. Живой предпросмотр рендерится в изолированном `<iframe>` без выполнения
   скриптов — если в дизайне есть CSS-анимация (`@keyframes`/`transition`),
   она проигрывается в предпросмотре, но экспорт в PNG/JPG/PDF всегда
   сохраняет только один статичный кадр.

**Про CapCut и видео/motion-дизайн**: у CapCut нет публичного API, поэтому
прямой интеграции (автоматически положить материал в проект CapCut,
прочитать/записать его файлы) в приложении нет и не планируется. Для
видео/анимационных роликов используйте раздел **🎨 Медиа** (там есть
генерация видео через Polza) — готовый `.mp4` можно вручную перетащить в
CapCut как обычный исходник.

## ✉️ Почта

Почтовый клиент поверх обычного IMAP/SMTP — работает с mail.ru «из
коробки» и с любым другим провайдером, который даёт доступ по IMAP/SMTP.

1. Раздел **Почта → Настройки**. В mail.ru: Настройки почты → Пароль и
   безопасность → Пароли для внешних приложений — создайте пароль именно
   для приложений, не используйте основной пароль от почты.
2. Впишите email и этот пароль, при необходимости поправьте хосты/порты
   (по умолчанию уже стоят `imap.mail.ru:993` / `smtp.mail.ru:465`).
   «Проверить соединение» проверяет и IMAP, и SMTP отдельно.
3. **Брендированная подпись** — имя, должность, компания, контакты,
   акцентный цвет и логотип (вставляется как встроенное изображение письма,
   не внешняя ссылка — не ломается в большинстве почтовых клиентов).
4. **Входящие** — последние 30 писем, чтение текста/HTML.
5. **Написать** — обычная форма отправки; подпись подставляется
   автоматически (можно отключить галочкой).
6. **«🤖 Черновик с ИИ»** — отдельный чат, который готовит текст письма.
   Готовый черновик переносится в «Написать» одной кнопкой, но **отправка
   всегда только вручную** — агент никогда не отправляет письма сам, только
   предлагает текст.

Пароль приложения хранится локально в файле `mail/account.json` внутри
папки данных (открывается через «Настройки → Открыть в проводнике») — как
и API-ключ модели, никуда, кроме указанных серверов почты, не уходит.

## 🐙 GitHub

Работа с вашими репозиториями прямо из приложения — через обычный GitHub
REST API (без установки Git на компьютер, ничего дополнительно ставить не
нужно).

1. **GitHub → Настройки**: вставьте Personal Access Token (GitHub → Settings
   → Developer settings → Personal access tokens; нужен скоуп `repo`).
   «Проверить» покажет, под каким логином подключились.
2. **Репозитории**: список ваших репозиториев (обновляется по кнопке),
   **«+ Создать репозиторий»** — новый пустой репозиторий (публичный или
   приватный) прямо из приложения.
3. Откройте репозиторий — слева дерево файлов: отметьте галочкой те, что
   нужны агенту для контекста (их содержимое подгружается и передаётся в
   чат, как документы проекта). Бинарные файлы (картинки, шрифты и т.п.)
   недоступны для прикрепления.
4. В чате попросите что-то объяснить или изменить — если нужна правка,
   агент предложит её карточкой (файл + новое содержимое целиком, не дифф) —
   нажмите **«Применить и закоммитить»**, и приложение создаст коммит прямо
   в репозитории на GitHub (в основную ветку) через API. Ничего не
   коммитится без явного нажатия кнопки. Карточка с предложенной правкой
   сохраняется и восстанавливается, если вы закрыли репозиторий и вернулись
   позже, не нажав «Применить»/«Отклонить».

## 🤖 Чат-боты и воронки

Встроенный конструктор чат-ботов с автоворонками для Telegram, ВКонтакте и
MAX — без отдельного сервера: приложение само опрашивает API площадок, пока
оно открыто.

1. **Чат-боты → Настройки**: для каждой площадки — свой токен:
   - **Telegram** — токен бота от [@BotFather](https://t.me/BotFather).
   - **ВКонтакте** — токен сообщества (Управление → Работа с API → Ключи
     доступа, права «Сообщения сообщества») + ID сообщества.
   - **MAX** — токен бота (создаётся аналогично Telegram, через бот-мастер
     платформы).

   «Проверить» подтверждает токен (показывает имя бота/сообщества),
   «Сохранить» — сохраняет его локально, «Запустить»/«Остановить» —
   включает или выключает опрос конкретной площадки.
2. **Воронки**: создайте воронку — название, одна или несколько площадок,
   триггер (конкретное слово/фраза во входящем сообщении, либо «первое
   сообщение от нового человека», либо «по умолчанию» — если ничего другое
   не подошло) и шаги: текст сообщения + задержка в минутах перед
   отправкой (0 — сразу). Шаги отправляются по очереди с нужной паузой,
   пока диалог открыт.
3. **Входящие**: список обращений по каждой площадке, переписка и поле для
   ручного ответа — можно вмешаться и ответить самой в любой момент, воронка
   при этом не мешает.

**Важное ограничение**: боты отвечают только пока приложение открыто и на
нужной площадке нажата «Запустить» — это не отдельный круглосуточный
сервер. Для мест с высоким или ночным трафиком, где нужна гарантированная
доступность 24/7, это стоит учитывать: пока приложение закрыто, бот не
отвечает и не ведёт по воронке.

## Сборка (для разработчика)

```bash
npm install
npm run electron:dev     # запуск с live-reload для разработки
npm run electron:start   # собрать и один раз запустить (без установки)
npm run electron:build:win    # собрать портативный .exe для Windows
npm run electron:build:linux  # собрать AppImage для Linux
npm run electron:build:mac    # собрать .zip для macOS (без подписи Apple)
```

Готовые файлы появляются в папке `release/`. Сборка под Windows/macOS с
Linux-машины не подписывается сертификатом разработчика — это ожидаемо для
личного инструмента; SmartScreen/Gatekeeper предупредят при первом запуске,
но запустить можно.

### Устройство проекта

- `electron/main.cjs` — главный процесс: вся работа с файловой системой
  (проекты/документы/навыки/чаты как файлы), диалоги выбора файлов/папок,
  сборка системного промпта (включая извлечение текста из `.docx`/`.doc`/
  `.xlsx`/`.pdf` — через `mammoth`, `word-extractor`, `exceljs`, `pdf-parse`),
  и экспорт сообщений в PDF/PNG (скрытое `BrowserWindow` рендерит HTML,
  `printToPDF`/`capturePage` сохраняют результат). Также здесь: чтение
  документов из связанной внешней папки проекта «на лету» (без копирования),
  и импорт навыков из файла/папки `SKILL.md` (простой разбор YAML-заголовка
  `name`/`description` + подстановка текстовых материалов рядом).
- `electron/ops.cjs` — операционка: листы как JSON (`{name, rows}`), импорт
  `.xlsx` через `exceljs`, сборка системного промпта агента операционки
  (текущие данные + формат предлагаемых правок), применение правок.
- `electron/mail.cjs` — почта: аккаунт/подпись в `mail/account.json`,
  IMAP через `imapflow` + `mailparser` (входящие), SMTP через `nodemailer`
  (отправка + генерация HTML-подписи с логотипом через `cid`-вложение);
  таймауты подключения укорочены (10–20 с вместо дефолтных ~90 с), чтобы
  недоступный сервер не подвешивал интерфейс.
- `electron/media.cjs` — медиагенерация: `POST /v1/media` → опрос
  `GET /v1/media/{id}` до `completed`/`failed` (интервал и лимит ожидания
  зависят от типа — картинка/видео/аудио) → скачивание результата и
  сохранение в `media/` (проекта или общую) вместе с JSON-метаданными
  (модель, промпт, дата, стоимость) для истории.
- `electron/github.cjs` — GitHub без локального Git: список/создание
  репозиториев, дерево файлов (`git/trees?recursive=1`), чтение и коммит
  файлов через Contents API (`GET`/`PUT /repos/{owner}/{repo}/contents/...`)
  — тот же механизм, что использует веб-редактор самого GitHub.
- `electron/chatbots.cjs` — чат-боты и воронки: адаптеры для Telegram
  (`api.telegram.org`), ВКонтакте (Bot API v5.199 + Long Poll сервера
  сообщества) и MAX (`platform-api2.max.ru` — формат восстановлен по
  исходникам стороннего клиента, официальная документация была недоступна
  из этой среды при разработке) с единым интерфейсом
  `testConnection`/`pollOnce`/`sendMessage`; общий цикл опроса на каждую
  запущенную площадку (с защитным минимальным интервалом между итерациями,
  чтобы аномально быстрый ответ сервера не «забивал» процесс приложения);
  подбор воронки по триггеру (слово → первое сообщение → по умолчанию);
  планировщик шагов воронки (проверка раз в 30 секунд, у кого из
  собеседников подошло время следующего шага).
- `electron/design.cjs` — раздел «Дизайн»: сохранённые дизайны как JSON-файлы
  (глобально или в `projects/<id>/design/`, как медиа), системный промпт
  дизайн-ассистента (с фирменным стилем проекта, если раздел к нему
  привязан). Экспорт переиспользует общий `exportHtmlToPdf/Png` из
  `main.cjs` плюс новые `exportHtmlToJpg`/`exportSvgToFile` (JPEG через
  `nativeImage.toJPEG()`, SVG — прямая запись текста без рендеринга).
  HTML/SVG от ассистента прогоняется через DOMPurify перед сохранением и
  показом (`src/lib/sanitizeDesign.ts`), живой предпросмотр — в `<iframe
  sandbox="">` без выполнения скриптов.
- `electron/preload.cjs` — безопасный мост `window.api` между интерфейсом и
  главным процессом (contextBridge, без прямого доступа к Node.js из
  интерфейса).
- `src/lib/api.ts` — стриминговый клиент OpenAI-совместимого
  `/chat/completions`, вызывается прямо из интерфейса; `listModels()` —
  `GET /models` (авторизация не обязательна на стороне Polza) для подсказок
  в полях выбора модели.
- `src/lib/markdownRender.ts` — единый рендер markdown → HTML (используется
  и в живом чате, и при экспорте): блок кода с языком `chart` (JSON:
  `{type, title, labels, series}`) распознаётся и рисуется как SVG-график
  через `src/lib/chartRender.ts` (bar/line/pie, без внешних библиотек и
  сетевых запросов), а не выводится как текст.
- `src/lib/exportHtml.ts` — сборка печатной HTML-версии сообщения/чата для
  экспорта в PDF/PNG, включая шапку/подвал фирменного стиля проекта
  (`BrandKit`) поверх общего рендера markdown.
- `src/lib/promptBuilder.ts` — разбор ответа конструктора навыков.
- `src/components/` — интерфейс (сайдбар, проект, чат, навыки, настройки).

## Ограничения текущей версии

- Поиск по документам не «умный» (без embeddings/RAG) — весь текст
  документов проекта подставляется в системный промпт целиком, с лимитом по
  объёму. Для очень больших баз знаний это может упираться в лимит контекста
  модели.
- Синхронизация между несколькими компьютерами не реализована — папка
  `Личный чат` живёт на одном устройстве (можно вручную скопировать папку
  или держать её в Google Диске/Яндекс Диске/Dropbox и т.п. для резервной
  копии).
- Операционка — это снапшот-таблицы, не живая копия Excel: формулы не
  пересчитываются, изменения в приложении не попадают обратно в исходный
  `.xlsx` (импорт — это разовое копирование данных внутрь приложения).
- Медиагенерация проверена end-to-end на подменённом (mock) API-ответе — сама
  структура запроса/опроса/скачивания соответствует официальной документации
  Polza.ai (`POST /v1/media`, `GET /v1/media/{id}`), но с реальным ключом и
  реальными моделями не тестировалась (нет доступа к внешним API в этой
  среде). Точные ID моделей и их параметры меняются на стороне Polza —
  сверяйтесь с polza.ai/models, если модель не найдена или вернула ошибку.
- GitHub-интеграция коммитит через Contents API (по файлу за раз, всегда в
  основную ветку репозитория) — это не полноценный Git: нет локальной
  истории, веток, merge, работы с большими бинарными файлами. Для реальной
  разработки это осознанно упрощённый режим быстрых точечных правок с
  ассистентом, а не замена `git`/Claude Code. Дерево репозитория и коммиты
  проверены сквозным сценарием на подменённом (mock) GitHub API — с реальным
  токеном не тестировалось (нет доступа к api.github.com из этой среды).
- Почтовый модуль реализован по стандартным протоколам IMAP/SMTP (через
  `imapflow`/`nodemailer`), но фактическое подключение к mail.ru не
  тестировалось живыми учётными данными — окружение сборки не имеет
  доступа к внешним IMAP/SMTP-серверам. Логика проверена насколько
  возможно без реального сервера (round-trip настроек, корректный тайм-аут
  и понятная ошибка при недоступном сервере) — при первом реальном
  использовании стоит внимательно проверить «Проверить соединение».
- Графики строятся ассистентом текстом (JSON-блок), а не выбором из
  готового набора — если модель отдаст некорректный JSON, вместо графика
  покажется понятное сообщение об ошибке, а не пустое место.
- Чат-боты/воронки работают только пока приложение открыто (см. раздел
  выше) — это не круглосуточный хостинг ботов. Сквозной сценарий
  (подключение → срабатывание триггера по входящему сообщению → отправка
  шага воронки → ручной ответ) проверен на подменённом (mock) Telegram
  API; ВКонтакте и MAX используют тот же проверенный код опроса/отправки и
  формат запросов, восстановленный из официальной/сторонней документации,
  но отдельно с моками не прогонялись и с реальными токенами не
  тестировались (нет доступа к api.telegram.org/vk.com/platform-api2.max.ru
  из этой среды). Перед боевым использованием стоит внимательно проверить
  «Проверить» на каждой площадке и протестировать воронку на себе.
- Автопостинг в соцсети (публикация постов, а не переписка ботом) — по
  вашему решению не делаем.
- Раздел «Дизайн» создаёт статичные материалы (HTML/SVG → PNG/JPG/PDF/SVG),
  а не видео — прямой интеграции с CapCut нет и не будет (у CapCut нет
  публичного API), для видео/motion-роликов используйте раздел «Медиа»
  (готовый файл переносится в CapCut вручную, как обычный исходник).
  Экспорт в SVG доступен только для дизайнов, изначально созданных как
  векторная графика — конвертации произвольного HTML-макета (пост/документ/
  презентация) в SVG нет, это технически ненадёжная задача без готового
  вменяемого решения. Пройден сквозной сценарий (создание HTML- и
  SVG-дизайна через подставленный ответ ассистента, сохранение, экспорт во
  все поддерживаемые форматы) — реальный вызов модели для генерации дизайна
  не тестировался (нет доступа к api Polza из этой среды).
