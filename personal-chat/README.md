# Личный чат

Персональное десктопное приложение: Claude-подобный чат с проектами (своя
инструкция + свои документы, как в Claude.ai), библиотекой навыков
(копирайтинг, делопроизводство и т.д.) и конструктором навыков с помощью ИИ.
Подключается к любой OpenAI-совместимой модели через
[Polza.ai](https://polza.ai) — своим API-ключом.

**Все данные — проекты, документы, чаты, навыки — хранятся обычными файлами
и папками прямо на вашем компьютере**, не в облаке и не в этом репозитории.
В репозитории — только программа.

## Установка (для пользователя — просто скачать и запустить)

Готовый файл для Windows собирается из этого проекта (см. раздел «Сборка»
ниже) и не требует установки — скачайте `.exe` и запустите двойным кликом.
При первом запуске Windows SmartScreen может показать предупреждение
«Windows защитила ваш компьютер» (потому что файл не подписан цифровой
подписью) — нажмите «Подробнее» → «Выполнить в любом случае».

## Как это устроено

При первом запуске приложение создаёт папку `Личный чат` в разделе
«Документы» на компьютере (её можно сменить в Настройках). Внутри:

```
Личный чат/
  projects/
    <название-проекта>/
      project.json      — инструкция, описание, подключённые навыки
      docs/              — обычные файлы: перетащите сюда .docx/.txt/.md,
                            приложение подхватит их автоматически
      chats/              — история переписки по проекту
      tasks/              — задачи по времени этого проекта
  skills/
    <название-навыка>.json
```

Кнопка «📁 Открыть папку проекта» в приложении открывает эту папку в
проводнике — можно работать с документами и через приложение, и напрямую
через файловую систему.

## Настройка подключения к модели

1. Раздел **⚙️ Настройки**.
2. Base URL по умолчанию — `https://polza.ai/api/v1` (OpenAI-совместимый
   эндпоинт Polza.ai). Можно указать любой другой совместимый сервис.
3. Вставьте свой API-ключ Polza.ai.
4. Укажите модель — поле «Модель» подгружает список моделей прямо с Polza.ai
   (кнопка «Обновить список», или начните печатать — появятся варианты).
   Список ничем не ограничен приложением: доступна **любая модель, какая
   включена на вашем аккаунте Polza.ai** — ID можно и вставить вручную, если
   не нашли в подсказках (например только что активировали новую).
5. Сохраните.

Ключ хранится только локально на компьютере (в системной папке настроек
приложения), никуда, кроме указанного адреса API, не отправляется. Никаких
ключей в самом репозитории/коде нет и быть не должно — держать реальные
API-ключи в git небезопасно, даже в приватном репозитории.

### Прокси / VPN

Если интернет идёт через прокси — блок **«Прокси / VPN»** в тех же настройках:

- **Откуда брать адрес** — из настроек Windows (по умолчанию), вручную
  (`http://адрес:порт`) или вообще без прокси. Ручной вариант нужен, когда
  прокси не прописан в Windows системно, а выдан вам просто адресом и портом.
- **Логин и пароль** — только если прокси их требует (признак — ошибка
  «407 Proxy Authentication Required»). Это данные от прокси, а не от Polza.
  Вписывать их надо в отдельные поля, а не внутрь адреса: адрес вида
  `http://логин:пароль@хост:порт` Chromium не принимает.
- **«Проверить соединение»** — делает настоящий запрос к API модели с теми
  значениями, что сейчас в форме (сохранять заранее не нужно), и говорит
  прямо: соединение работает, прокси недоступен, или пароль не подошёл.

Настройки применяются сразу после сохранения, перезапускать приложение не нужно.

Для прокси по SOCKS5 авторизация по логину/паролю не поддерживается (это
ограничение Chromium, а не приложения) — если прокси с паролем, используйте
вариант `http://`.

В подсказках поля «Модель» (и полей моделей в «Медиа») всегда доступен
заготовленный список часто используемых моделей — работает даже если живой
запрос списка к Polza.ai не удался (например, при слабом интернете):
`anthropic/claude-sonnet-5`, `anthropic/claude-opus-5`,
`anthropic/claude-fable-5`, `google/gemini-3.5-flash-lite`,
`moonshotai/kimi-k3` (чат); `google/gemini-3.1-flash-lite-image`,
`google/gemini-3.1-flash-image-preview` (изображения);
`seedance-2-mini`, `seedance-2`, `kling/v3-motion-control`,
`topaz/video-upscale` (видео) — все через один и тот же ключ Polza.ai, без
отдельных ключей на каждый провайдер. Список задан в
`src/lib/curatedModels.ts` — если Polza переименует/уберёт модель, форма
всё равно примет любой введённый вручную ID, просто поправьте константу.

Модель не обязательно менять в общих настройках — прямо над полем ввода в
любом диалоговом окне чата есть своё поле «Модель»: оно переопределяет
модель только для этого конкретного чата (сохраняется вместе с ним) и тоже
подсказывает и заготовленный список, и живой каталог Polza.ai; ссылка
«сбросить к настройкам» возвращает чат на модель по умолчанию.

Ответ модели по умолчанию не ограничивается коротким текстом — `Max tokens`
в настройках стоит на 16 000, этого достаточно для длинных документов вроде
контентных воронок или договоров на несколько тысяч слов. При необходимости
можно поднять ползунок ещё выше (до 64 000) — предел по факту зависит от
того, что поддерживает выбранная модель на стороне Polza.ai.

## 🌐 Доступ в интернет

Ассистент умеет искать в интернете и читать страницы по ссылке — сам, когда для
ответа нужны свежие данные (новости, цены, что публикуют конкуренты). Включается
в **⚙️ Настройки → Доступ в интернет** (по умолчанию включён).

Как это работает: модель не ходит в сеть напрямую — она просит приложение
выполнить поиск или открыть страницу, приложение делает запрос и отдаёт результат
обратно модели, и так до 4 раз за один ответ. В чате видно строку «🌐 Ищу в
интернете: …», чтобы было понятно, чем ассистент занят. Итоговый ответ должен
содержать ссылки на источники.

Два поисковика на выбор:

- **DuckDuckGo** (по умолчанию) — ключ не нужен, работает сразу после установки.
  Но это обычная поисковая страница, а не официальный API: при частых запросах
  может ответить ошибкой или пустым результатом.
- **Tavily** — поисковый сервис, сделанный специально для ИИ-ассистентов
  (бесплатный ключ на [tavily.com](https://tavily.com)). Стабильнее; переключайтесь
  на него, если DuckDuckGo начнёт подводить.

Поиск работает и в **задачах по расписанию**, которые выполняются без вас — это
и был основной смысл: задача «Что делают конкуренты» по средам сама сходит в
интернет и соберёт свежую сводку.

## Проекты

- **Переименование** — наведите курсор на проект в левой панели и нажмите
  значок ✎ рядом с названием (или дважды кликните по названию) — поле
  становится редактируемым, Enter сохраняет, Esc отменяет.
- **Что видит ассистент** — над окном чата есть ссылка «Что видит ассистент
  (N симв.)»: разворачивает ровно тот системный промпт (инструкции + навыки
  + документы проекта + документы из связанной папки), который реально
  уходит модели вместе с каждым сообщением. Если кажется, что ассистент не
  следует навыку или не видит документ из связанной папки — первым делом
  сюда: если контента там нет, дело в том, что подключить (галочка навыка,
  путь к папке), если есть — модель его просто не выполнила, это уже вопрос
  к самой инструкции/навыку или к качеству модели.
- **Инструкции** — системный промпт: роль ассистента, стиль, правила.
- **Документы** — файлы в папке `docs/` проекта. Распознаются автоматически:
  Word (`.docx`), старый Word (`.doc`), Excel (`.xlsx`), PDF (текстовый слой),
  `.txt`, `.md`, `.csv`, `.json`, `.rtf` (упрощённое извлечение). Старый
  формат `.xls` и отсканированные PDF без текстового слоя не читаются —
  пересохраните файл как `.xlsx`/текстовый PDF или вставьте текст вручную.
- **Папка на компьютере** — вместо копирования файлов в проект можно один раз
  указать существующую папку на вашем компьютере (вкладка «Документы» →
  «Папка на компьютере»). Файлы из неё не копируются и никуда не
  перемещаются — ассистент читает их прямо оттуда при каждом обращении к
  проекту, так что изменения в исходных файлах подхватываются автоматически.
  Поддерживаются те же форматы, что и для обычных документов.
- **Файлы прямо в чате** — кнопка **«+»** слева от поля ввода открывает обычный
  проводник: выберите любой файл на любом диске, не копируя его в проект. Текстовые
  документы (`.docx`, `.pdf`, `.xlsx`, `.txt`, `.md`, …) читаются целиком;
  изображения передаются модели как картинка — но только если выбранная модель
  умеет «видеть» (Claude, Gemini умеют); видео и аудио передаются как ссылка на
  файл с названием и размером — их содержимое модели напрямую не уходит, поэтому
  по ним ассистент опирается на то, что вы расскажете. Прикреплённые файлы видны
  плашками над полем ввода (крестик убирает) и остаются в истории чата.
- **Дизайн-система проекта** — вкладка «Дизайн» → «Дизайн-система проекта»:
  привяжите файл или целую папку с дизайн-системой, сохранённой у вас на
  компьютере. Файлы не копируются, читаются на месте, правки подхватываются сами.
  Текстовые файлы и `.svg` ассистент читает целиком, картинки видит по названиям.
  Учитывается в чате проекта и в фирменных выгрузках документов.
- **Навыки** — подключаются из общей библиотеки.
- Несколько независимых чатов внутри проекта, история сохраняется как файлы.
  Чат можно переименовать: наведите на него в списке и нажмите ✎. Название
  сохраняется, автоматическое переименование по первому сообщению его не
  перезаписывает.
- **Экспорт в PDF, PNG, Word и Excel** — под каждым сообщением в чате (и над
  списком сообщений — для всего чата целиком) есть ссылки на все четыре
  формата. Открывается системный диалог сохранения, по умолчанию — прямо в
  папку `docs/` текущего проекта, так что готовый документ сразу становится
  частью базы знаний проекта.

  Разница между парами форматов важна на практике:

  - **PDF и PNG** — это картинка готовой страницы: фирменная шапка, цвета,
    подвал с контактами. Отправить клиенту, распечатать, положить в презентацию.
  - **Word (`.docx`)** — настоящий документ, который открывается и правится:
    заголовки остаются заголовками, списки — списками, таблицы — таблицами
    Word. Не картинка и не «HTML, притворяющийся документом».
  - **Excel (`.xlsx`)** — каждая таблица из ответа становится отдельным листом
    с настоящими ячейками: контент-план, смета, разаллокация сразу готовы к
    работе. Числа записываются числами (их можно складывать), а не текстом;
    значения с единицами («45 000 ₽», «27%») остаются текстом, чтобы не
    потерять смысл. Весь текст, который не был таблицей, попадает на
    отдельный лист «Текст» — ничего из ответа не теряется.
- **Дизайн (фирменный стиль)** — вкладка проекта «Дизайн»: название бренда,
  слоган, акцентный цвет, логотип, текст подвала (реквизиты/контакты). Всё
  это автоматически применяется и к экспорту в PDF/PNG (шапка с логотипом,
  акцентный цвет в заголовках/таблицах, подвал), и к графикам/оформлению
  прямо в чате этого проекта — так документы, которые готовит ассистент,
  сразу выглядят фирменно, без ручного форматирования.
  Дополнительно можно загрузить **QR-код** и указать **телефон/e-mail**: если
  QR-код загружен, шапка документа перестраивается в три зоны — логотип
  слева, название и слоган по центру, а телефон и e-mail (если заполнены) и
  QR-код — справа, с одинаковым отступом от края. Без QR-кода шапка остаётся
  в простом виде (логотип + название/слоган слева).
  Есть и третий вариант — **загрузить готовую шапку целиком одной картинкой**
  (кнопка «Загрузить готовую шапку целиком»): тогда она используется как
  есть, поля выше на саму шапку не влияют (акцентный цвет и подвал документа
  продолжают применяться).
- **Визуализация данных** — ассистент может строить настоящие графики
  (столбчатые, линейные, круговые) прямо в ответе — просто попросите
  визуализировать данные. Графики рендерятся как SVG (не как картинка с
  сервера) и попадают как в живой чат, так и в экспортированные PDF/PNG.

### Задачи по времени

Как в Claude — над списком чатов проекта есть раздел **«Задачи»**: разовые
или повторяющиеся поручения ассистенту, которые выполняются сами, без вашего
участия. Кнопка **«+ Задача»** открывает форму: название, текст задания
(что должен сделать ассистент), периодичность — один раз (с датой), каждый
день или каждую неделю (с днём недели) — и время выполнения.

Приложение проверяет задачи каждые 30 секунд (пока оно запущено) и в нужный
момент отправляет текст задания ассистенту с системным промптом текущего
проекта — результат появляется новым чатом в списке «Чаты» ниже, с названием
«Задача: …», как будто вы задали вопрос сами. Разовая задача после выполнения
автоматически отключается; ежедневные и еженедельные продолжают выполняться
по расписанию — их можно временно выключить галочкой или удалить совсем.
Задачи выполняются, только пока приложение запущено — оно не работает в
фоне при закрытом окне.

### Перенос своих проектов из Claude.ai

Кнопка **«Импорт из Claude.ai (.json)»** в боковой панели принимает файлы
экспорта проектов Claude.ai в исходном формате (`name`, `description`,
`prompt_template`, `docs[]`) — так переносятся инструкции и документы в
локальный проект (файлы документов создаются прямо в папке `docs/`).

### Задачи по расписанию и их выдачи

Результаты задач лежат **отдельным списком** «Выполнено по расписанию» — над чатами, но не среди них.
Еженедельная задача выдаёт результат каждую неделю, и раньше эти выдачи вытесняли из списка те
разговоры, которые вы вели руками. Выдача открывается только на чтение (продолжать переписку
с самой собой задача не должна) и удаляется отдельно от чатов.

### Один документ в двух местах

Если файл лежит **и в документах проекта, и во внешней папке**, подключённой к тому же проекту, он
раньше уходил в модель двумя копиями и оплачивался дважды на каждом сообщении. Теперь дубль
пропускается, а в конце промпта появляется строка о том, какие файлы не продублированы, — чтобы
пропуск не выглядел как потерянный документ.

Одинаковыми считаются файлы с совпавшими именем и размером. Если имя то же, а размер другой — это
разные версии, и обе остаются: иначе приложение молча спрятало бы вашу правку.

### Удаление проекта

Наведите курсор на проект в списке слева — рядом с ✎ появится **✕**. Приложение переспросит и назовёт
проект по имени: вместе с ним удаляются его чаты, документы и задачи по расписанию.

Папка проекта уходит **в корзину компьютера**, а не стирается сразу — проект нередко удаляют «на
всякий случай», обнаружив потом, что в его документах лежал единственный экземпляр договора. Если
корзина почему-то недоступна (сетевой диск, флешка), приложение удалит папку насовсем и **скажет об
этом** отдельным сообщением, а не сделает необратимое молча.

Документы, подключённые к проекту **из внешней папки** на компьютере, не трогаются вообще: в проекте
хранился только путь к ним.

## Профиль проекта — контекст для остальных разделов

Разделы Word, Excel, визуализации, клининга и документооборота работают с файлом или папкой и о вас
не знают ничего — а решения принимают такие, для которых это знание нужно: как назвать документ, в
какой логике разложить папки, чей это вообще бизнес.

Раньше этот пробел затыкался примерами прямо в коде, и приложение оказывалось «заряжено» одним
конкретным бизнесом. **Это убрано:** в коде не осталось ни одного названия компании, контрагента или
проекта — теперь контекст берётся только из того, что вы завели у себя.

Во вкладке **«Инструкции»** каждого проекта есть блок **«Профиль проекта»**. По кнопке приложение
одним запросом к модели собирает короткое резюме в JSON: чем вы занимаетесь, о чём проект, ключевые
клиенты и бренды, принятые у вас правила именования. Это несколько строк вместо сотен тысяч символов
базы знаний — их и получают остальные разделы.

Профиль **не пересобирается сам**: это отдельный оплаченный запрос. Когда в проект добавляются
документы или меняются инструкции, он помечается как **«устарел»** — пересобрать или нет, решаете вы.

В справке, которая уходит агенту, прямо написано не переносить данные одного проекта в задачу по
другому: именно смешение проектов и заметно как «агент опять приплёл не тот бизнес».

## Навыки и конструктор навыков

Раздел **🧩 Навыки** — общая библиотека переиспользуемых инструкций.
Подключается к нужным проектам на вкладке проекта «Навыки».

Кнопка **«✨ Создать навык с помощью ИИ»** открывает диалог: опишите задачу,
ассистент задаст уточняющие вопросы и предложит готовый навык — нажмите
«Сохранить как новый навык».

Готовые навыки можно **импортировать** — как в Claude:
- **«Загрузить из файла (.md, .skill)»** — обычный текстовый файл (расширение
  роли не играет) с YAML-заголовком (`name:`, `description:`) и текстом
  инструкции после него; если заголовка нет, имя берётся из названия файла,
  а весь текст становится инструкцией.
- **«Загрузить из папки (SKILL.md)»** — папка с файлом `SKILL.md` (тот же
  формат заголовка) и, при необходимости, дополнительными материалами рядом
  (`.txt`, `.docx`, `.xlsx`, `.pdf` и т.д.) — их текст автоматически
  подставляется в навык вслед за основной инструкцией.

В обоих случаях импортированный навык открывается в редакторе для проверки —
ничего не сохраняется автоматически, пока вы не нажмёте «Сохранить навык».

### Разовый вызов навыка прямо в диалоге

Кроме постоянного подключения навыка ко всему проекту (вкладка «Навыки»),
в любом диалоговом окне чата над полем ввода есть кнопка **«🎯 Вызвать
навык»** — она подключает выбранный навык только к следующему отправляемому
сообщению (видно как отдельную плашку с крестиком для отмены), не меняя
настройки самого проекта. Удобно, когда навык нужен разово, для одного
конкретного запроса.

### Почему навык теперь соблюдается точнее

Вызванный к сообщению навык раньше лежал только в системной части запроса — далеко от самого вопроса,
и на длинном контексте (проект с документами, открытый файл) его параметры терялись: модель помнила
общий смысл навыка, но пропускала формат, количество пунктов и ограничения.

Теперь навык, во-первых, помечен как **инструкция к исполнению, а не справка**, с прямым указанием
выполнять все параметры буквально и говорить вслух, если что-то выполнить нельзя. Во-вторых, короткое
напоминание про навык дописывается **последней строкой запроса** — туда, где модель читает
внимательнее всего.

## 📗 Excel

Работа с настоящими файлами Excel, которые лежат у вас на компьютере — **с живым
пересчётом формул**. Файл остаётся на своём месте и служит источником правды —
приложение работает прямо с ним, а не с копией данных внутри себя.

- **«Открыть файл»** — выберите любой `.xlsx` на любом диске. Листы становятся
  вкладками, формулы подсвечиваются цветом, при наведении видно саму формулу.
- **«Новая книга»** — пустая таблица прямо в приложении. Она живёт в памяти, пока
  вы не нажмёте «Сохранить»: тогда приложение спросит, куда положить файл.
- **Строка формул** сверху — как в Excel: выберите ячейку, впишите значение или
  формулу с `=` и нажмите Enter.
- **Пересчёт настоящий.** Меняете оклад — сразу пересчитываются ставка в час,
  реальный расход, итоги по команде и вообще всё, что от них зависит, включая
  формулы на других листах. Порядок вычисления строится по графу зависимостей,
  круговые ссылки не зацикливают приложение, а помечаются как `#CIRCULAR!`.
- **«Сохранить»** пишет обратно в тот же файл, сохраняя оформление, форматы
  чисел, ширину столбцов и листы, которых вы не касались. «Сохранить как…» —
  в новый файл.
- **Форматы чисел** учитываются при показе: ячейка с форматом `#,##0" ₽"`
  выводится как `1 270 000 ₽`, с `0.0%` — как `36,2%`.
- **Формулы можно писать через `;`**, как показывает русский Excel
  (`=ЕСЛИ`-стиль: `=IF(A1>0;A1;0)`). Приложение переводит разделитель в тот вид,
  который требует формат `.xlsx`; текст в кавычках и массивы `{1;2}` не трогаются.

### 🤖 Агент Excel

Кнопка **«🤖 Агент Excel»** открывает чат, которому видно всю книгу — значения и
формулы. Он умеет три вещи.

1. **Считать по книге.** Прежде чем что-то предлагать, агент может выполнить
   формулу или прочитать кусок листа прямо в живой книге — например
   `=SUMIFS(Продажи!D2:D500; Продажи!B2:B500; "Ромашка")`. Ничего при этом не
   меняется, ответ приходит агенту, а вы видите строку «🧮 Считаю по книге…».
   Это значит, что цифры в его выводах взяты из таблицы, а не прикинуты на глаз.
2. **Строить таблицы с формулами.** Агент может предложить целую таблицу —
   заголовки, строки данных, итоги через `SUM`/`SUMIFS`, проценты формулой, —
   и при необходимости **создать под неё новые листы** (скажем, «Данные» и
   «Свод» со ссылками между ними). Форматы чисел он тоже расставляет сам.
3. **Править отдельные ячейки**, как раньше.

Любое изменение сначала показывается как предложение — одной строкой: сколько
ячеек и на каких листах, какие листы будут созданы. «Показать ячейки» разворачивает
подробности, если они нужны. Как только вы нажали «Применить» (или «Отклонить»),
плашка исчезает и больше не возвращается — даже если снова открыть агента. После
применения книга пересчитывается целиком, а файл на диске меняется только когда вы
нажмёте «Сохранить».

**Агент открывается сбоку от таблицы**, а не вместо неё: таблицу видно, можно
кликнуть по ячейке и нажать «🤖 Спросить про B7» — вопрос про эту ячейку (с её
формулой и значением) подставится в поле ввода сам. Для больших задач вроде
сопоставления двух листов есть «⤢ Развернуть агента» — там разговор занимает всё
окно, как раньше. Под полем ввода есть 🎯 — можно подключить навык, например с
вашими правилами расчётов.

Движок формул — `fast-formula-parser` (MIT) плюс наш модуль
`electron/excelFunctions.cjs`, закрывающий пробелы библиотеки: там около 50
функций оставлены заглушками, среди которых такие повседневные, как `MAX`, `MIN`,
`MEDIAN`, `SUMIFS`, `MATCH`, `TEXTJOIN`. Проверено на вашем `dinamika_ops_full.xlsx`:
**893 формулы, все 893 совпали с тем, что посчитал сам Excel.**

### Правку видно до того, как вы её приняли

Пока агент печатает ответ, затронутые ячейки подсвечиваются прямо в таблице и показывают новое
значение вместо старого (старое остаётся в подсказке при наведении). Ничего не записывается в файл,
пока вы не нажмёте «Применить», — подсветка просто показывает, что именно изменится. Та же логика,
что и у правок абзацев в Word.

## 📘 Word

То же самое, но для документов: договоры, техзадания, коммерческие предложения —
`.docx`, которые лежат у вас на компьютере.

- **«Открыть файл»** — документ раскладывается на пронумерованные блоки:
  заголовки, абзацы, пункты списков, таблицы. Номер слева — не украшение: именно
  им оперирует агент, когда предлагает правку.
- **Правка руками** — выберите блок, отредактируйте текст в поле сверху.
  Кнопками рядом можно вставить новый абзац (обычный, заголовок или пункт списка)
  или удалить блок.
- **«🤖 Агент Word»** открывается сбоку: документ остаётся виден, можно нажать
  «Спросить про блок 3» — вопрос с текстом этого блока подставится сам. Агент
  видит документ целиком и предлагает правки списком («заменить блок 4»,
  «вставить заголовок после 6», «удалить 9»); применяете вы. Под полем ввода
  есть 🎯 — можно подключить навык, например с правилами оформления договоров.
- **«Сохранить»** пишет обратно в тот же файл.

**Что при этом происходит с документом.** Приложение не пересобирает `.docx`
заново — оно находит в исходном файле точные границы правленого абзаца и меняет
только их. Проверено: после правки в архиве документа отличается ровно один файл
(`word/document.xml`), всё остальное — стили, нумерация, шрифты, колонтитулы,
картинки — байт в байт как было.

Единственное осознанное ограничение: если внутри абзаца было смешанное
начертание («**Исполнитель:** Агентство Динамика» — первое слово жирным), то
после правки весь абзац примет вид первого фрагмента. Приложение предупреждает об
этом прямо под полем редактирования. Текст внутри таблиц пока правится только в
самом Word — агент об этом знает и скажет словами, что нужно поменять.

### Правки и анализ — два режима

Над чатом агента переключатель:

- **Правки** — агент меняет только то, о чём вы попросили; остальной текст и всё форматирование
  остаются как были. Правка **подсвечивается прямо в документе, пока агент её печатает**: старый
  текст зачёркнут, новый под ним — видно, что именно изменится, ещё до подтверждения. Применяете вы,
  файл на диске меняется только после «Сохранить» (есть и «Сохранить как» — в любую папку).
- **Анализ** — разбор без правок: ошибки, противоречия между пунктами, размытые формулировки, риски,
  выводы, отчёт по документу. Сам документ в этом режиме не меняется, а результат сохраняется
  **отдельным документом** по кнопке.

**Каждое открытие документа — новый разговор.** Прошлая работа по этому же файлу не восстанавливается:
она мешает агенту и заново оплачивается на каждом запросе.

## 📁 Документооборот

Договоры, акты, ТЗ и счета по вашим типовым шаблонам. Ничего не загружается внутрь приложения —
хранятся **только пути** к вашим файлам. Поправили реквизиты или шаблон у себя в папке — следующий
документ уже с новыми.

### Справочники (настраиваются один раз)

| Что | Зачем |
|---|---|
| **Контрагенты** | Файл с реквизитами каждого — он подставляется в документ |
| **Шаблоны** | Типовые договор, акт, ТЗ, акт сверки (.docx) |
| **Исходники** | Тарифы, прайсы — то, откуда берутся цифры |
| **Документ сверки** | По нему считается следующий номер, в него пишется каждая выдача |
| **Папки** | Архив всех документов и папка, куда сохранять готовые |

### Как делается документ

1. Выбираете вид (договор / акт / ТЗ / счёт), месяц, шаблон, контрагента, при необходимости —
   данные: выгрузки Excel и CSV, отчёты, **скриншоты статистики**.
2. Нажимаете «Собрать задание» — приложение читает всё перечисленное, **само считает номер и дату**
   и отдаёт агенту.
3. Пишете, что отличается от шаблона (или просто «подготовь по шаблону»).
4. Агент заполняет шаблон и показывает результат. По кнопке документ сохраняется **и в Word, и в
   PDF**, а в документ сверки дописывается строка: номер, дата, контрагент, сумма.

**Номер и дата считаются приложением, а не моделью.** Это принципиально: «посмотри крайний номер и
прибавь единицу» — ровно та арифметика, которую модель периодически делает неправильно, а цена
ошибки в документе высокая. Правила даты вшиты по виду документа: у **акта** — последнее число
месяца, у **ТЗ** — первое, у договора и счёта — сегодняшняя.

**Форматирование шаблона сохраняется полностью.** Документ не собирается заново — в исходном .docx
заменяются только те абзацы, где меняются данные. Колонтитулы, печати, поля, стили и всё, чего
приложение вообще не понимает, остаются байт в байт. Сам шаблон при этом не меняется — сохраняется
копия.

Документ за прошлый месяц можно приложить вместо шаблона и сказать «по тем же реквизитам» — агент
возьмёт из него и структуру, и реквизиты.

### Режим юриста

Вкладка **«Юрист»** — документ с нуля, без шаблона, на ваших условиях. Агент составляет его так,
чтобы он защищал ваши интересы и не противоречил закону, и **прямо называет оставшиеся риски** и те
условия, которые юридически не сработают. Сохраняется так же — в Word и PDF.

### Про PDF

Если на компьютере установлен Word, PDF печатается **настоящим Word** — файл совпадает с тем, что вы
увидите, открыв документ у себя. Если Word не найден, PDF собирает само приложение: структура
сохраняется, но вёрстка приблизительная — приложение об этом честно пишет под сохранённым файлом,
чтобы такой PDF не ушёл контрагенту непроверенным.

Проверка:

```bash
node electron/smoke-docflow.cjs
xvfb-run -a npx electron electron/smoke-docflow-ui.cjs
```

## 📊 Визуализация данных

Дашборды, диаграммы, майнд-карты, блок-схемы, таймлайны и карточки-списки. Источник — то, что уже
лежит у вас на диске: таблица, документ, **скриншот выгрузки** — или просто текст в чате. Ничего не
копируется внутрь приложения, результат кладётся в указанную папку.

Настраивается перед сборкой:

- **Что построить** — дашборд, один график, майнд-карта, блок-схема, таймлайн, карточка-список,
  сравнение.
- **Размер** — пост 1080×1350, квадрат, история, слайд 1920×1080, лист A4, дашборд 1400×1000.
- **Палитра** — четыре готовых (в том числе фирменная и градиентная), с возможностью **переопределить
  любой цвет вручную**: акцент, цвет текста и каждый цвет ряда данных отдельно.
- **Пожелания по стилю** — словами: «минимализм, крупные цифры, без рамок».

Готовый макет показывается в предпросмотре и сохраняется в **PNG, PDF и HTML** одновременно (форматы
выбираются галочками). HTML кладётся рядом намеренно: это единственный формат, в котором макет потом
можно поправить, не собирая заново.

**Про точный размер.** Снимок окна ограничен высотой экрана, поэтому высокий макет (история 1080×1920
на ноутбуке) снимается полосами и склеивается обратно — файл получается ровно заявленного размера, а
не обрезанным по экрану. Это проверяется тестом, который читает размер из заголовка самого PNG.

Графики рисуются разметкой SVG — без библиотек и без обращений в интернет: в сохранённом файле не
будет ничего, что могло бы не загрузиться у получателя.

## 💹 Финмодель

Финансовая модель проекта: прогноз продаж, доходы и расходы, налоги, окупаемость, точка
безубыточности, NPV и IRR. На выходе — книга Excel в указанной папке и заключение экономиста.

### Что считает код, а что агент

Это главное решение раздела. **Все числа считает код** — детерминированно, по формулам. Модель,
в которой цифры придумала языковая модель, бесполезна: её нельзя ни проверить, ни защитить перед
инвестором, а ошибка в одной цифре тянет за собой всю таблицу.

**Агент делает ровно две вещи, которые коду не по силам**, и делает их в два прохода:

1. **До расчёта** — читает вашу статистику и выводит из неё кривую спроса: базовый объём,
   сезонность по месяцам, скорость выхода на мощность. Заодно ищет в официальных источниках
   инфляцию (Росстат, Банк России), действующий МРОТ и ставку по вашему режиму — с указанием,
   откуда взял. Всё это подставляется в форму, и приложение пишет, что именно подставило.
2. **После расчёта** — видит уже посчитанные числа и пишет по ним заключение: вердикт, за счёт
   чего модель сходится, риски с указанием, какая цифра ломается, какие рычаги и на сколько
   двигать, чего не хватает в данных.

Порядок здесь не случаен: если поменять проходы местами, заключение будет написано по придуманным
числам — а это ровно то, ради чего финмодель не делают.

### Если продаж ещё не было

Стартапу можно подложить выгрузку **Вордстата**. Продаж там нет, есть спрос — и агент берёт из
динамики запросов только *форму* кривой: сезонность и скорость роста. Уровень продаж из Вордстата
не выводится, его задаёте вы базовым объёмом; агент может предложить свою оценку, но обязан
сказать, из чего она вышла.

### Что заполняется

Название проекта, продукт и цена за единицу (средняя, если продуктов несколько), себестоимость,
система налогообложения, ФОТ построчно (должность, сколько человек, оклад, процент от продаж),
постоянные расходы, переменные расходы (фиксированной суммой в месяц, на единицу или процентом от
выручки), инвестиции, сезонность, раскрутка, инфляция по годам и особенности бизнес-модели словами.

### Книга на живых формулах

Книга собирается **формулами, а не готовыми числами**. Поменяв в Excel цену или объём, вы получите
пересчёт, а не поедете обратно в приложение. Листы: «Исходные», «Ставки», три расчётных листа по
сценариям (пессимистичный, базовый, оптимистичный), «Итоги» и «Заключение».

**Ставки лежат отдельной таблицей, а не внутри формул.** Налоговое законодательство меняется, и
модуль, который «знает» ставку намертво, однажды начнёт молча врать. Поэтому ставка налога,
страховые взносы, МРОТ, порог НДС и ставка дисконтирования — это ячейки со ссылкой на источник и
пометкой «проверьте». Формулы ссылаются на них, и поправить ставку можно прямо в Excel.

Что учтено в расчёте, помимо очевидного:

- **Страховые взносы ступенью по МРОТ.** Льготный тариф малого бизнеса действует не на всю
  зарплату: до МРОТ — общий тариф, и только часть сверх него — льготный. Плоские 15% занижают ФОТ
  примерно на треть, а недооценённые взносы — самая частая причина, по которой модель сходится на
  бумаге и не сходится в жизни.
- **Правила, которые работают за год, а не за месяц.** Минимальный налог на УСН «Доходы минус
  расходы» (1% от выручки даже при убытке) и НДС при превышении порога выручки на упрощёнке
  считаются от годовой выручки и вынесены в отдельные колонки — месячной формулой они не
  выражаются, а сложить их в колонку месячного налога нельзя: формула начала бы ссылаться сама
  на себя.
- **Инфляция с индексацией по годам.** Первый год базовый, каждый следующий растёт к предыдущему.
- **Взносы по каждой должности отдельной колонкой** — чтобы ФОТ можно было проверить глазами,
  а не принимать на веру.

Единственное, что записано числом, а не формулой, — **IRR**: она решается подбором, и встроенный
просмотрщик таблиц приложения такую функцию не считает. Это прямо подписано в книге; в самом Excel
её можно перепроверить формулой ВСД по колонке «Денежный поток».

### Как это проверено

Книга не просто создаётся — тест загружает её обратно, пересчитывает **тем же движком, которым
приложение считает таблицы**, и сверяет ячейка за ячейкой с тем, что посчитал код. Если формула в
книге разойдётся с расчётом, человек увидит одни числа на экране и другие в Excel; этого не
случится молча.

## 🧹 Клининг

Разбор папок и сверка документов в них.

### Разбор папки

Даёте папку — агент смотрит, что в ней лежит (имена, даты, а у документов ещё и начало текста), и
предлагает план: какие подпапки создать, что куда перенести, что переименовать. Он продолжает **вашу**
логику, а не свою: если папки называются «июль», «август», а по датам внутри видно год, он предложит
переименовать их в «июль 2025», «август 2026» и дальше держаться этого формата. Скриншоты собирает
отдельно, документы группирует по проекту и периоду.

Работа идёт кругами: агент предлагает план — вы его одобряете — приложение раскладывает файлы само,
руками перекладывать ничего не нужно. После каждого круга папка **перечитывается заново**, поэтому
«Продолжить разбор» агент делает уже по её текущему состоянию, а не по устаревшей описи, и может
разбирать большую папку в несколько заходов.

Три правила, на которых это построено — потому что речь о ваших файлах:

1. **Одобрение перед каждым кругом.** Агент показывает план целиком (что создать, что куда
   перенести), и только после «Выполнить» приложение это делает. Отдельная кнопка на каждый круг —
   не перестраховка: каждый круг это ещё один оплаченный запрос к модели.
2. **Удаления не существует.** Команды удаления нет ни в протоколе, ни в исполнении: разобрать папку
   можно перемещением, а «прибраться» ценой потерянного файла — нельзя. Ненужное складывается в
   отдельную папку.
3. **Вся уборка отменяется одной кнопкой.** Журнал копится по всем кругам, поэтому «Отменить»
   возвращает папку в то состояние, в котором она была **до начала работы**, а не до последнего
   шага — включая имена папок.

Плюс: ни один путь не может выйти за пределы выбранной папки (проверяется перед каждой операцией, а
не только при разборе плана), а при совпадении имён файл сохраняется как «Акт 41 (2).docx» — ничего
не затирается.

### Сверка документов

Вторая вкладка. Агент читает документы в папке и собирает книгу Excel из четырёх листов:

| Лист | Что в нём |
|---|---|
| **Договоры** | Номер, дата, предмет, контрагент — с приложениями строками под своим договором |
| **Акты** | Номер (если есть), дата, предмет, сумма, контрагент |
| **ТЗ** | Номер (если есть), дата, предмет, сумма, контрагент |
| **Счета** | Номер, дата, сумма, основание (договор/акт/ТЗ), контрагент |

В последнем столбце каждой строки — имя файла, из которого взяты данные: по нему вы проверите, а не
поверите на слово. Чего в документе нет, остаётся пустым — придумывать агенту запрещено.

**Ограничение:** содержимое дочитывается у первых 40 документов, дальше идут только имена — прочитать
сотню договоров целиком дороже, чем стоит вся сверка. Приложение честно пишет об этом в описи.

Проверка:

  файл скачивается и сохраняется локально; сам процесс отменить нельзя, но
  можно просто закрыть карточку и не ждать результата.

## ☁️ Облако

Подключение к **Яндекс Диску** и **Google Диску**: смотреть папки, скачивать файлы
(в том числе сразу в документы проекта — тогда файл становится частью его базы
знаний) и загружать файлы обратно в облако.

**Подключение Яндекса.** На oauth.yandex.ru создаётся приложение, и Яндекс выдаёт
**Client ID** и **Client secret**. Это не токен — это ключи, по которым приложение
само просит у Яндекса токен для вашего аккаунта. Впишите их на вкладке
«Подключение», нажмите «Подключить»: откроется окно входа в Яндекс, вы
подтверждаете доступ, и токен сохраняется здесь, на компьютере. Пароль от аккаунта
приложение не видит и не хранит.

**Аккаунтов может быть несколько.** У каждого свой Диск и **свой Директ**. Список
аккаунтов — на вкладке «Подключение»: точкой отмечен активный, его можно
переименовать (чтобы не путаться в логинах) или отключить. Активный аккаунт —
общий для всего приложения: и «Файлы» здесь, и раздел «📣 Директ» работают с ним.
Переключить его можно в двух местах — в этом списке и селектором в шапке Директа.

Одно приложение на oauth.yandex.ru годится для всех аккаунтов: Client ID и secret
вписываются те же самые, различаться будет только аккаунт, под которым вы войдёте в
открывшемся окне.

**Окно входа каждый раз открывается «с нуля»** — в собственной чистой сессии, без
запомненного входа. Иначе второй аккаунт добавить было невозможно: Яндекс видел куки
уже подключённого аккаунта, молча возвращал код для него же, и приложение бодро
рапортовало «подключено», хотя в списке по-прежнему был один аккаунт. Плюс к этому
Яндексу передаётся `force_confirm=yes`, чтобы экран подтверждения показывался всегда,
а не проскакивал незаметно.

Если всё же подключить аккаунт, который уже есть в списке, он обновится, а не
задвоится (приложение сверяет их по логину, который сообщает сам Яндекс) — и
приложение прямо об этом скажет, вместо того чтобы показать «подключено ✓» при
неизменившемся списке.

У каждого аккаунта своя переписка с агентом Директа: анализ по одному бизнесу не
попадёт в чат по другому. При отключении аккаунта его переписка удаляется вместе
с ним.

Если вставить Client ID в поле токена, любой API Яндекса ответит сухим
«Не авторизован» — приложение теперь так и объясняет эту ошибку, вместо того чтобы
пересказывать её дословно. Токены Яндекса конечны: refresh-токен сохраняется вместе
с основным, и просроченный токен продлевается автоматически, без повторного входа.

**Google Диск** подключается по-прежнему готовым OAuth access-токеном (как его
получить — написано прямо в интерфейсе).

Google-документы (Docs/Sheets/Slides) нельзя скачать «как есть» — они
автоматически экспортируются в `.docx`/`.xlsx`/`.pptx`, и приложение само
дописывает нужное расширение.

**NotebookLM подключить нельзя** — у него нет публичного API: Google не
предоставляет ни адресов для запросов, ни прав доступа к нему, так что
подключаться попросту не к чему. Обходной путь: выгрузить материалы из
NotebookLM в Google Документы, а их уже читать отсюда через Google Диск.

## 📣 Яндекс Директ

Работа с рекламным аккаунтом через Yandex Direct API v5 — на **том же токене
Яндекса**, что и Диск. Одно приложение на oauth.yandex.ru может держать оба права
сразу; важно только отметить права Яндекс.Директа при его создании.

- **Кампании** — выберите период и нажмите «Загрузить данные». Приложение подтянет
  список кампаний, отчёт по эффективности за период (показы, клики, CTR, расход,
  средняя цена клика, конверсии) и ключевые фразы работающих кампаний со ставками.
- **Агент** — чат, которому видны все эти цифры. Спрашивайте «где сливается
  бюджет», «какие фразы отключить», «что не так со структурой». Он опирается на
  загруженные данные, а не на общие соображения, и объясняет решения цифрами.
  Под полем ввода есть 🎯 — можно подключить свой навык, например с правилами
  ведения рекламы для конкретного клиента.
- **Изменения — только с подтверждением.** Агент может предложить остановить или
  запустить кампанию либо изменить ставку фразы. Предложение показывается отдельной
  плашкой с причиной; пока вы не нажмёте «Применить в Директе», в аккаунте ничего
  не меняется.
- **Логин клиента** нужен только агентским аккаунтам, ведущим рекламу за клиента.
  Для собственного аккаунта поле оставьте пустым. Он хранится у самого аккаунта
  Яндекса, а не у раздела: у разных аккаунтов он разный, и у части его нет вовсе.
- **Переключение аккаунта** — селектором в шапке раздела. При переключении таблица
  и переписка агента очищаются: показывать кампании одного аккаунта под именем
  другого было бы хуже, чем показать пустой экран.

## 🤖 Чат-боты и воронки

У бота два режима работы на выбор — **ИИ по базе проекта** и **сценарные воронки**.

### Бот на ИИ (рекомендуется)

В карточке площадки поставьте галочку **«Отвечать с помощью ИИ по базе проекта»**
и выберите проект. Дальше бот отвечает собеседникам в мессенджере сам, опираясь
на инструкции, навыки и документы этого проекта — то есть консультирует строго
в рамках вашей базы знаний, а не как «универсальная нейросеть». Он помнит
переписку с каждым человеком отдельно (последние 20 сообщений) и, если включён
доступ в интернет, может при необходимости туда сходить.

Бот проинструктирован писать по-человечески и коротко, как в переписке (без
markdown и таблиц), и честно говорить «не знаю, давайте свяжу с человеком»
вместо того чтобы выдумывать цены и условия, которых нет в проекте.

Пока проект не выбран, ИИ-ответы не отправляются. В ИИ-режиме воронки для этой
площадки не срабатывают — иначе на одно сообщение приходили бы два ответа сразу.


Встроенный конструктор чат-ботов с автоворонками для Telegram, ВКонтакте и
MAX — без отдельного сервера: приложение само опрашивает API площадок, пока
оно открыто.

1. **Чат-боты → Настройки**: для каждой площадки — свой токен:
   - **Telegram** — токен бота от [@BotFather](https://t.me/BotFather).
   - **ВКонтакте** — токен сообщества (Управление → Работа с API → Ключи
     доступа, права «Сообщения сообщества») + ID сообщества.
   - **MAX** — токен бота (создаётся аналогично Telegram, через бот-мастер
     платформы). Под токеном есть поле **«Адрес API»**: у MAX бот-API
     встречается на разных хостах, и «Проверить» перебирает известные,
     подставляя в это поле тот, который ответил — останется нажать
     «Сохранить». Обычно трогать это поле не нужно.

   «Проверить» подтверждает токен (показывает имя бота/сообщества),
   «Сохранить» — сохраняет его локально, «Запустить»/«Остановить» —
   включает или выключает опрос конкретной площадки.
2. **Воронки**: создайте воронку — название, одна или несколько площадок,
   триггер (конкретное слово/фраза во входящем сообщении, либо «первое
   сообщение от нового человека», либо «по умолчанию» — если ничего другое
   не подошло) и шаги: текст сообщения + задержка в минутах перед
   отправкой (0 — сразу). Шаги отправляются по очереди с нужной паузой,
   пока диалог открыт.
3. **Входящие**: список обращений по каждой площадке, переписка и поле для
   ручного ответа — можно вмешаться и ответить самой в любой момент, воронка
   при этом не мешает.

### Если MAX пишет про сертификат

Ошибка вида `net::ERR_CERT_AUTHORITY_INVALID` — это не проблема токена и не
ошибка приложения: Windows не доверяет сертификату сайта, поэтому соединение
обрывается ещё до всякого запроса. Так бывает с российскими сервисами,
сертифицированными «Российским доверенным корневым сертификатом» Минцифры —
Windows его с собой не приносит. Лечится один раз и навсегда:

1. На [gosuslugi.ru](https://www.gosuslugi.ru/) найдите страницу «Установка
   сертификатов» и скачайте корневой сертификат Минцифры.
2. Откройте скачанный файл → «Установить сертификат» → «Локальный компьютер» →
   «Поместить все сертификаты в следующее хранилище» → **«Доверенные корневые
   центры сертификации»**.
3. Перезапустите приложение.

Если вы выходите в интернет через корпоративный прокси, который «подписывает»
трафик своим сертификатом, тот сертификат нужно установить тем же способом.
Приложение теперь пишет это словами вместо кода ошибки — и в результате
проверки, и в строке состояния бота.

**Важное ограничение**: боты отвечают только пока приложение открыто и на
нужной площадке нажата «Запустить» — это не отдельный круглосуточный
сервер. Для мест с высоким или ночным трафиком, где нужна гарантированная
доступность 24/7, это стоит учитывать: пока приложение закрыто, бот не
отвечает и не ведёт по воронке.

## Фирменные цвета

Интерфейс, графики и все экспортируемые документы используют палитру Агентства
Динамика.

| Роль | Цвет |
|---|---|
| Акценты | `#FF2F6D` → `#B23CC4` → `#00D9FF` |
| Розовый градиент | `#FF2F6D` → `#FF6F9C` |
| Голубой градиент | `#00D9FF` → `#7DEBFF` |
| Фоны | `#F7ECE7` (тёплый, боковая панель) и `#F7F6F3` (нейтральный, рабочая область) |
| Текст | `#0A0A0A` основной, `#20262C` заголовки |

Гамма намеренно сдержанная: цвета фирменные, но площадь у них небольшая. Основа —
нейтральные поверхности и почти чёрный текст; фирменный розовый работает точечно:
тонкая линия под активной вкладкой, полоска слева у выбранного пункта меню, ссылки,
кольцо фокуса. Основные кнопки — почти чёрные: в инструменте, где готовят договоры и
сметы, цветные заливки читаются несерьёзно. Полный градиент остался ровно в одном
месте — на названии приложения, где он звучит как логотип, а не как оформление.

**Два оттенка добавлены расчётом, и это не самовольство, а требование читаемости.**
Фирменные цвета выбраны для заливок, а не для текста:

- `#FF2F6D` на светлом фоне даёт контраст 3.3:1 при норме 4.5:1 — ссылками и
  подписями его набирать нельзя. Для текста используется затемнённый вариант того же
  цвета `#C4004A` (5.6:1). Заливки, рамки и градиенты при этом остаются фирменными.
- Белый текст на чистом `#FF2F6D` — 3.6:1, поэтому заливка кнопок начинается с чуть
  притемнённого `#E01F5C` (4.7:1) и уходит в фирменный `#B23CC4`.
- `#00D9FF` и `#7DEBFF` на светлом фоне нечитаемы в принципе (1.6:1 и 1.4:1), поэтому
  работают только как заливка под тёмным текстом и как конец градиента.
- Оба фирменных цвета текста почти одинаково тёмные, поэтому для приглушённых
  подписей добавлен `#5A626B` из той же холодной гаммы.

Проверено в собранном приложении: весь текст интерфейса проходит норму WCAG AA.

**Цвета серий на графиках** — отдельная история. Рампа «розовый → фиолетовый → циан»
аналоговая, из неё не выходит шести цветов, различимых между собой (в том числе при
дальтонизме), поэтому палитра серий проверена алгоритмически и выглядит так:
`#FF2F6D`, `#7B3FD4`, `#0095B0`, `#8A6A00`, `#B23CC4`, `#0E8C7A`, `#C4004A`. Циан
затемнён до `#0095B0` (иначе линию просто не видно), а охра `#8A6A00` в бренд не
входит, но без неё четвёртая серия сливается с остальными. Первые четыре цвета
различимы в любых сочетаниях, дальше — только соседние, поэтому легенда с подписями
рисуется всегда.

В экспортируемых документах (PDF, PNG, Word, Excel) действует то же правило: рамки,
шапки таблиц и линии — фирменным цветом, текст — его читаемым вариантом. Затемнение
считается автоматически от того акцентного цвета, который задан в фирменном стиле
проекта, так что это работает и для любого другого бренда, а не только для Динамики.

## Производительность и обслуживание

Коротко: место на диске — не проблема, длина переписки — проблема.

Всё хранится обычными файлами. Текст занимает копейки: чат из 150 сообщений — это
около 300 КБ. Реально место занимают только сгенерированные картинки и видео в папке
`media`, и их видно в разделе «Настройки» → «Обслуживание» (кнопка «Посмотреть, что
занимает место» покажет размеры по папкам и самые тяжёлые чаты).

По-настоящему растёт другое: **модель перечитывает диалог целиком при каждом
ответе**. Чем длиннее чат, тем дороже и медленнее каждый следующий ответ, а после
определённой длины запрос просто перестаёт помещаться в контекст модели. Поэтому:

- Приложение отправляет модели только последнюю часть переписки — примерно 120 тысяч
  символов (около 60 тысяч токенов). Если что-то не поместилось, модель об этом
  предупреждена в системном промпте, а вы видите строку «Чат длинный: N ранних
  сообщений уже не помещаются в память модели».
- Там же кнопка **«Свернуть историю в резюме»**. Она сначала сохраняет полный текст
  ранних сообщений в файл (`chats/archive/<чат>-<дата>.json`), потом просит модель
  сжать их до сути — решения, формулировки, цифры, договорённости, открытые вопросы —
  и оставляет в чате только последние сообщения плюс это изложение. Ничего не
  теряется, чат снова становится лёгким.
- Практическое правило: не ведите всю работу за год в одном чате. Отдельная задача —
  отдельный чат внутри проекта; общая база знаний живёт в документах и инструкциях
  проекта, а не в истории переписки.

Второе, за чем стоит следить, — **документы проекта**: они целиком попадают в
системный промпт (до 60 000 символов на файл). Двадцать больших документов в одном
проекте — это долгий и дорогой каждый запрос. Держите в проекте то, что реально
нужно ассистенту, остальное — в подпапках, которые не привязаны.

## Нужно ли где-то регистрировать это приложение

Нет. Это личный инструмент, который работает на вашем компьютере и никому ничего не
предоставляет как услугу — регистрировать его как ПО, включать в реестр или
уведомлять кого-либо не требуется.

Что действительно имеет отношение к закону — не само приложение, а то, что вы через
него делаете, и это ровно те же обязанности, что и без него:

- **Персональные данные.** Если через чат-ботов вы собираете контакты клиентов
  (имя, телефон, переписку), вы — оператор персональных данных: нужно уведомление в
  Роскомнадзор и согласие людей на обработку. Это обязанность агентства, а не
  приложения; она возникает от самого факта сбора контактов, где бы они ни лежали.
- **Маркировка рекламы (ОРД/ЕРИР).** Не меняется: тексты, сгенерированные здесь,
  маркируются так же, как любые другие.
- **Ключи и токены** от Polza, Яндекса, GitHub, мессенджеров — это доступ к вашим
  аккаунтам и деньгам. Они лежат только на этом компьютере, в открытом виде.
  Полнодисковое шифрование (BitLocker) и пароль на вход в Windows — разумный
  минимум, особенно на ноутбуке.
- **Условия сервисов.** Действуют правила Polza, Яндекса и площадок, к которым вы
  подключаетесь; приложение — просто клиент к их API.

## Кастомные сборки: plugins.json

Приложение при запуске читает файл `plugins.json` рядом с `package.json` (в собранной
версии — в ресурсах). Он задаёт название приложения и то, какие разделы в него входят:

```json
{
  "productName": "Тексты Динамики",
  "modules": {
    "projects": true, "skills": true, "word": true,
    "excel": false, "docflow": true, "dataviz": true, "cleanup": false, "media": false,
    "cloud": false, "direct": false, "github": false, "chatbots": false
  }
}
```

Выключенный раздел исчезает из меню и не открывается, даже если попасть в него иначе.

**База одинакова у всех сборок и не отключается:** чат с выбором модели, проекты и инструкции,
навыки, задачи по расписанию, работа с файлами на компьютере, сохранение результатов
(`projects`, `skills`). Плюс «Настройки». Всё остальное — Excel, Word, Медиа, Облако,
Документооборот, Визуализация, Финмодель, Клининг, Директ, GitHub, Боты — опциональные плагины.

**Если файла нет — включено всё.** Обычная сборка ведёт себя ровно как раньше, так что
отсутствие или порча файла не может оставить кого-то без разделов.

Руками этот файл писать не нужно: его создаёт раздел **«Сборки»** в приложении «Личный код»
(папка `personal-code` в этом же репозитории) — там набор разделов выбирается галочками и
выгружается сюда одной кнопкой. Файл добавлен в `.gitignore`: это локальная конфигурация
конкретной сборки, а не часть кода.

Проверка того, что механизм работает:

```bash
xvfb-run -a npx electron electron/smoke-plugins.cjs
```

## Демо-версии для тестовой группы

Если рядом с `package.json` (в собранной версии — в ресурсах) лежит `licence-config.json`,
сборка становится демо-версией: при запуске она просит файл активации.

```json
{
  "publicKey": "<открытый ключ подписи>",
  "revocationUrl": "https://ваш-адрес/revoked.json",
  "productName": "Личный чат"
}
```

Как это работает для тестировщика: приложение показывает **код его компьютера**, он присылает
код автору, получает в ответ файл `.lic` и открывает его. Копия работает на этом компьютере до
даты, указанной в файле. За неделю до конца срока в приложении появляется полоска с обратным
отсчётом.

Файлы активации выдаёт раздел **«Демо-доступ»** в приложении «Личный код» (папка
`personal-code`) — там же создаётся ключ подписи и выгружается список отзыва. Подробности,
включая честную оценку того, от чего это защищает, а от чего нет, — в README «Личного кода».

Копия подписывается **именем из лицензии**: у одного тестировщика в окне «Личный чат Марии»,
у другого — «Личный чат Василия». Имя задаётся при выдаче доступа, сборка при этом одна и та же.

**Без `licence-config.json` проверки нет вообще.** Обычная сборка никогда не спросит активацию,
так что собственную рабочую копию заблокировать невозможно. Файл добавлен в `.gitignore`.

## Сборка с предустановленным ключом

Если рядом лежит `managed-config.json`, ключ доступа к моделям берётся из него, а поле ключа в
настройках не показывается — вместо него раздел **«Расход моделей»**: какие модели использованы
за день, неделю и месяц, сколько токенов и на какую сумму.

```json
{
  "apiKey": "<ключ Polza для тестовой группы>",
  "baseUrl": "https://polza.ai/api/v1",
  "model": "anthropic/claude-sonnet-5",
  "currency": "₽",
  "prices": { "anthropic/claude-sonnet-5": { "input": 300, "output": 1500 } }
}
```

Цены — за миллион токенов. Модель, для которой цена не задана, показывается с токенами, но без
суммы, и общий итог в этом случае тоже не выводится: сумма, молча не учитывающая половину
расхода, хуже, чем её отсутствие.

Расход считается точно, если сервис вернул `usage`; если нет — по длине текста, и такие строки
помечены словом «оценка». Приложение сначала запрашивает точный расход
(`stream_options.include_usage`), а если шлюз это поле не принимает — повторяет запрос без него.

**Честно про ключ:** он лежит внутри приложения на компьютере тестировщика. Скрытие поля — про
аккуратность (не скопируют, не покажут на скриншоте), а не про стойкость. Заводите для группы
отдельный ключ с небольшим балансом: возможность его отозвать — и есть настоящая защита.

Файл создаётся в разделе «Демо-доступ» приложения «Личный код» и добавлен в `.gitignore`.

## Предустановленные навыки

Файлы `.json` в папке `bundled-skills` рядом с `package.json` — навыки, вшитые автором сборки.
Тестировщик видит их название и описание и может подключить к проекту, но **текст навыка не
передаётся в окно приложения** и не редактируется: он вырезается на границе между главным
процессом и интерфейсом, поэтому его нет и в инструментах разработчика.

Навыки, которые тестировщик пишет сам, остаются полностью видимыми и редактируемыми — разница
только для предустановленных.

Тот же честный предел: текст лежит в приложении на чужом компьютере, и распаковавший установщик
его достанет.

Папку заполняет вкладка «Плагины» в «Личном коде»; она в `.gitignore`.

Проверки:

```bash
node electron/smoke-licence.cjs                    # выдача, отзыв, срок, подделки
node electron/smoke-managed.cjs                    # ключ в сборке, учёт расхода, скрытие навыков
xvfb-run -a npx electron electron/smoke-gate.cjs   # экран активации, имя копии, расход, навыки
```

## Скорость ответа

Ответ начинается не мгновенно по одной главной причине: **вся база знаний проекта уходит
модели заново с каждым сообщением**. Замер на проекте из пяти документов:

| | |
|---|---|
| системный промпт | 206 000 символов ≈ 69 000 токенов |
| уходит на сервер за одно сообщение | 370 КБ |
| после снятия галочек с трёх документов | 62 000 символов (−70%) |

Чем больше уезжает, тем дольше модель читает вход до первого слова. Поэтому у каждого
документа в проекте есть галочка **«отдавать ассистенту»**: снятая означает, что файл
остаётся в проекте, но не уходит в запрос. Когда промпт переваливает за ~90 000 символов,
рядом с «Что видит ассистент» появляется подсказка об этом.

Что ещё убрано из задержки:

- **Разбор документов кэшируется** по пути, времени правки и размеру. Раньше `.docx`, `.pdf`
  и `.xlsx` разбирались заново при каждой пересборке промпта — при каждом переключении
  вкладки. Замер: 123 мс → 8 мс.
- **Картинки чата кэшируются** в памяти окна. Раньше каждое сообщение перечитывало с диска
  и кодировало в base64 все картинки за всю историю чата — по ~55 мс на снимок в 1,5 МБ,
  на каждый ответ.

Замер воспроизводится:

```bash
xvfb-run -a npx electron electron/bench-chat.cjs
```

Он же работает как тест: падает, если кэш перестал работать или галочки перестали влиять
на промпт.

## Кэш промпта — главная статья экономии

В связке «проект с документами + навык» весь этот контекст оплачивается заново на каждом
сообщении. По разбору реальной выгрузки Polza за 24–30 августа: **76% счёта — это вход**, и
**0 токенов пришло из кэша** — кэш не использовался вообще.

Приложение теперь просит провайдера кэшировать неизменную часть. Для этого системное сообщение
разделено на две части:

- `stable` — инструкции проекта, документы, постоянные подсказки. Идёт **первой** и одинакова
  от запроса к запросу; на ней стоит метка кэша.
- `variable` — вызванный к сообщению навык, пересказ свёрнутой истории. Идёт **после**.

Порядок здесь не косметика: кэш совпадает по НАЧАЛУ промпта, и раньше вызванный навык
вклинивался в середину, ломая совпадение на каждом сообщении, где его меняли.

Метка ставится только для моделей Claude — у остальных она рискует сломать запрос без всякой
пользы. Если шлюз её не принял, приложение снимает поле и повторяет запрос: человек получает
ответ, а не ошибку, и больше метка в этом сеансе не шлётся.

**Проверить, работает ли это, можно в «Расходе моделей»**: там столбец «Из кэша». Если он
пустой при большом входе — появляется предупреждение. Это важно: подтвердить работу кэша можно
только на живом ответе провайдера.

Выключается галочкой в настройках.

Проверка:

```bash
xvfb-run -a npx electron electron/smoke-cache.cjs
```

Она гоняет настоящий чат и проверяет: метка стоит на первом блоке; неизменная часть побайтово
одинакова между сообщениями; для не-Claude модели и при выключенной настройке метки нет; при
отказе шлюза ответ всё равно приходит, а повтор уходит уже без метки.

Чего это **не** ускоряет: само время модели и сеть. Если и после снятия лишних документов
ответ идёт долго — дело в выбранной модели или в канале, и это видно по тому, что пауза не
зависит от размера проекта.

### Задачи по расписанию и ИИ-боты — та же метка

Чат — не единственное место, где раунды повторяют один и тот же контекст: задача по
расписанию, которая исследует интернет несколько раундов подряд («что нового у
конкурентов», еженедельный дайджест), раньше собирала системное сообщение отдельным
кодом в главном процессе и метку кэша не ставила вовсе — каждый раунд поиска заново
оплачивал полный контекст проекта. Реальный случай: 4–5 раундов на один недельный
дайджест обходились в ~600 ₽/день. Теперь и задачи по расписанию, и ИИ-боты в
мессенджерах используют ту же логику, что и обычный чат.

Отдельно был и второй баг, усиливавший первый: планировщик сканирует задачи раз в 30
секунд, а `nextRunAt` сдвигается только когда задача полностью выполнится — если прогон
занимал дольше 30 секунд (а несколько раундов поиска обычно занимают), следующий тик
находил ту же задачу «просроченной» и запускал её ещё раз. Одна еженедельная задача на
практике превращалась в 4 параллельных чата и 4-кратный счёт. Теперь выполняющиеся
задачи отслеживаются по id и не подхватываются повторно, пока прогон не завершится.

Проверка:

```bash
node electron/smoke-tasks-dedup.cjs
xvfb-run -a npx electron electron/smoke-tasks-cache.cjs
```

Первая — без Electron, дёргает планировщик напрямую и подтверждает, что «тик» во время
ещё идущего прогона не запускает задачу повторно. Вторая гоняет настоящую задачу по
расписанию через фейковый сервер и проверяет: раунды веб-поиска используют одну и ту
же помеченную кэшем неизменную часть; расход кэша учитывается в «Расходе моделей»;
создаётся ровно один чат задачи, а не несколько.


Готовые файлы появляются в папке `release/`. Сборка под Windows/macOS с

### Устройство проекта

- `electron/main.cjs` — главный процесс: вся работа с файловой системой
  (проекты/документы/навыки/чаты как файлы), диалоги выбора файлов/папок,
  сборка системного промпта (включая извлечение текста из `.docx`/`.doc`/
  `.xlsx`/`.pdf` — через `mammoth`, `word-extractor`, `exceljs`, `pdf-parse`),
  и экспорт сообщений в PDF/PNG (скрытое `BrowserWindow` рендерит HTML,
  `printToPDF`/`capturePage` сохраняют результат). Также здесь: чтение
  документов из связанной внешней папки проекта «на лету» (без копирования),
  и импорт навыков из файла/папки `SKILL.md` (простой разбор YAML-заголовка
  `name`/`description` + подстановка текстовых материалов рядом).
- `electron/ops.cjs` — операционка: листы как JSON (`{name, rows}`), импорт
  `.xlsx` через `exceljs`, сборка системного промпта агента операционки
  (текущие данные + формат предлагаемых правок), применение правок.
  `blankMergedContinuations()` корректирует то, как `exceljs` отдаёт
  объединённые ячейки: библиотека копирует значение объединённой ячейки во
  все столбцы, которые она визуально занимает, так что строка-заголовок
  раздела, объединённая на всю ширину листа, без этой правки превращалась в
  «мусорную» строку-дубликат при импорте — оставляем значение только в
  первой (реальной) ячейке объединения, остальные становятся пустыми;
  `worksheet.eachRow({ includeEmpty: true }, ...)` важен именно для этого —
  индексы объединений в `.xlsx` заданы в абсолютных номерах строк листа, и
  без `includeEmpty` (которое раньше молча пропускало пустые строки-разделители)
  эти индексы расходились бы с массивом импортированных строк.
- `electron/media.cjs` — медиагенерация: `POST /v1/media` → опрос
  `GET /v1/media/{id}` до `completed`/`failed` (интервал и лимит ожидания
  зависят от типа — картинка/видео/аудио) → скачивание результата и
  сохранение в `media/` (проекта или общую) вместе с JSON-метаданными
  (модель, промпт, дата, стоимость) для истории.
- `electron/github.cjs` — GitHub без локального Git: список/создание
  репозиториев, дерево файлов (`git/trees?recursive=1`), чтение и коммит
  файлов через Contents API (`GET`/`PUT /repos/{owner}/{repo}/contents/...`)
  — тот же механизм, что использует веб-редактор самого GitHub.
- `electron/chatbots.cjs` — чат-боты и воронки: адаптеры для Telegram
  (`api.telegram.org`), ВКонтакте (Bot API v5.199 + Long Poll сервера
  сообщества) и MAX (хост настраивается; по умолчанию перебираются
  `botapi.max.ru` и `platform-api2.max.ru`, токен уходит и заголовком
  `Authorization`, и параметром `access_token`, потому что разные версии
  площадки принимают его по-разному; формат восстановлен по исходникам
  стороннего клиента — официальная документация была недоступна из этой среды
  при разработке) с единым интерфейсом
  `testConnection`/`pollOnce`/`sendMessage`; общий цикл опроса на каждую
  запущенную площадку (с защитным минимальным интервалом между итерациями,
  чтобы аномально быстрый ответ сервера не «забивал» процесс приложения);
  подбор воронки по триггеру (слово → первое сообщение → по умолчанию);
  планировщик шагов воронки (проверка раз в 30 секунд, у кого из
  собеседников подошло время следующего шага).
- `electron/tasks.cjs` — задачи по времени: хранятся как JSON-файлы в
  `projects/<id>/tasks/`, `computeNextRun()` считает следующее срабатывание
  для разовых/ежедневных/еженедельных задач; тот же планировщик (проверка
  раз в 30 секунд), что и у воронок чат-ботов выше, только вызывает не
  адаптер площадки, а `runScheduledTask()` в `main.cjs` — тот собирает
  системный промпт проекта (`buildSystemPrompt`), отправляет задание модели
  нестримингово (`callModelOnce`) и создаёт из результата обычный чат в
  списке чатов проекта.
- `electron/websearch.cjs` — поиск и чтение страниц. Два провайдера: DuckDuckGo
  (разбор HTML-выдачи, без ключа — включая распаковку их редиректных ссылок вида
  `/l/?uddg=`) и Tavily (обычный JSON API по ключу). `runTools()` — единая точка
  выполнения: разбирает блок `===WEB SEARCH===`/`===WEB FETCH===` из ответа
  модели, выполняет запрос и возвращает готовый текст для следующего сообщения.
  Её вызывают и чат (через IPC), и задачи по расписанию, и ИИ-боты — так что
  формат блока и его обработчик физически не могут разойтись. Ошибки поиска
  возвращаются текстом, а не бросаются: неудачный запрос не должен ронять весь
  ответ, модель должна суметь сообщить о нём пользователю.
- `electron/netFetch.cjs` — весь исходящий трафик главного процесса. Node-овский
  `fetch` не видит системный прокси вообще, а у `net.fetch` из Electron нет
  способа ответить на запрос авторизации прокси: событие `app.on("login")`
  приходит только для запросов, принадлежащих окну (то есть из интерфейса), а
  запросы главного процесса до него не доходят и возвращаются голым 407 —
  проверено на реальном локальном прокси с Basic-авторизацией. Вариант с
  логином внутри адреса прокси Chromium отвергает (`ERR_NO_SUPPORTED_PROXIES`).
  Поэтому здесь `net.request`, у которого есть собственное событие `login`,
  обёрнут в fetch-совместимый вид (тело буферизуется и отдаётся штатному
  `Response`, так что `.ok/.json()/.text()/.arrayBuffer()/.headers` работают как
  обычно). На повторный запрос авторизации в рамках одного запроса отвечаем
  отказом — иначе Chromium уходит в ~30 попыток с тем же неверным паролем
  вместо понятного 407.
- `electron/excel.cjs` + `electron/excelFunctions.cjs` — живые книги Excel:
  загрузка через `exceljs` с сохранением объекта книги (поэтому запись обратно не
  теряет оформление), модель «лист → карта ячеек A1», пересчёт по графу
  зависимостей (`DepParser` сообщает, что читает каждая формула, дальше —
  топологический обход с обнаружением циклов). Объединённые ячейки схлопываются
  до одной, как и в `ops.cjs`, иначе заголовок дублируется по всем колонкам.
  `excelFunctions.cjs` реализует функции, которые библиотека оставила пустыми
  (`() => {}`), — её диспетчер превращает `undefined` в «функция не реализована»,
  и без этих реализаций обычная рабочая книга не пересчитывалась. Там же —
  протокол агента: блок `===EXCEL EDIT START===` разбирается в список изменений
  по листам (целая таблица через `ROWS:`, отдельные ячейки через `CELLS:`,
  форматы через `FORMAT:`; несуществующий лист создаётся), а блок
  `===EXCEL TOOL===` даёт агенту читать диапазоны и выполнять формулы по живой
  книге — без изменений, поэтому и без подтверждения, как у веб-поиска.
- `electron/yandexAuth.cjs` — OAuth Яндекса, общий для Диска и Директа: сборка
  ссылки авторизации, окно входа со слежением за навигацией (код подтверждения
  приезжает в адресной строке), обмен кода на токен и обновление по refresh-токену.
  Каждое подключение идёт в собственной сессии с уникальным именем раздела (без
  префикса `persist:`, то есть в памяти) — с одной общей сессией Яндекс отдавал код
  для уже подключённого аккаунта, не показывая экран входа вовсе.
  Ручной ввод кода оставлен как запасной путь: приложение, зарегистрированное так,
  что Яндекс только показывает код на странице, ничего не кладёт в URL.
- `electron/direct.cjs` — Яндекс Директ API v5: кампании, группы, объявления,
  фразы, отчёт по эффективности (отдельный TSV-эндпоинт, который умеет отвечать
  «отчёт ещё готовится» — здесь это обрабатывается повтором с ожиданием) и две
  операции изменения (пауза/запуск кампании, ставка фразы), обе за подтверждением.
  Денежные величины в API — микроединицы валюты; пересчёт спрятан здесь.
- Переписка с агентом в Excel и Word привязана к открытому файлу: она хранится
  вместе с ключом (путь к документу) и при открытии другого файла начинается заново.
  Прошлые разговоры не копятся — иначе агент продолжал бы обсуждать документ,
  которого уже нет на экране.
- `electron/word.cjs` — живые документы Word. Не пересобирает `.docx`, а находит в
  исходном `word/document.xml` точные границы каждого абзаца и заменяет только их,
  поэтому всё, чего нет в модели приложения (стили, колонтитулы, картинки,
  нумерация, поля), остаётся нетронутым. Сканер границ считает вложенность по
  полному имени тега: `<w:pPr>` и `<w:pStyle>` тоже начинаются с `<w:p`, и поиск по
  префиксу принимал их за вложенные абзацы — из-за этого документ выглядел одним
  сплошным абзацем. Вставки и удаления применяются от конца документа к началу,
  иначе они сдвигали бы номера блоков, которые пользователь только что подтверждал.
- `electron/exportDocs.cjs` — экспорт чата в Word и Excel. Принципиально не
  использует HTML: лексер `marked` разбирает markdown ответа на блоки
  (заголовки, абзацы, списки, код, таблицы), а дальше они собираются в
  настоящие абзацы и таблицы Word (`docx`) или в ячейки листов Excel
  (`exceljs`). Поэтому таблица из ответа приходит в Excel редактируемой, а не
  снимком экрана. `marked` в 18-й версии — только ESM, поэтому подключается
  одним кэшированным динамическим `import()`.
- `electron/cloud.cjs` — несколько аккаунтов Яндекса (список + id активного; старый
  формат с единственным аккаунтом читается и переносится в список на лету, чтобы уже
  подключённый аккаунт не пришлось подключать заново) и Яндекс Диск (`cloud-api.yandex.net`, адресация по пути)
  и Google Drive (`googleapis.com/drive/v3`, адресация по id файла) за общим
  интерфейсом `list/download/upload`. Google-документы экспортируются в форматы
  Office, потому что скачать их напрямую нельзя.
- `electron/preload.cjs` — безопасный мост `window.api` между интерфейсом и
  главным процессом (contextBridge, без прямого доступа к Node.js из
  интерфейса).
- `setWindowOpenHandler` в главном окне — Electron по умолчанию просто
  ничего не делает по клику на `<a target="_blank">` (открытие нового окна
  запрещено, если не назначить обработчик); все внешние ссылки в интерфейсе
  (создание токена GitHub, каталог моделей Polza и т.д.)
  теперь открываются в обычном браузере через `shell.openExternal`.
- Сетевые запросы из главного процесса (GitHub, чат-боты, медиа) идут через
  `net.fetch` из Electron, а не через встроенный `fetch` Node.js — так они
  используют тот же сетевой стек и системные настройки прокси, что и
  запросы из интерфейса (чат), и одинаково отвечают на запрос авторизации
  прокси (`app.on("login", ...)`, использует логин/пароль прокси из
  Настроек, если заданы).
- `src/lib/api.ts` — стриминговый клиент OpenAI-совместимого
  `/chat/completions`, вызывается прямо из интерфейса; `listModels()` —
  `GET /models` (авторизация не обязательна на стороне Polza) для подсказок
  в полях выбора модели.
- `src/lib/markdownRender.ts` — единый рендер markdown → HTML (используется
  и в живом чате, и при экспорте): блок кода с языком `chart` (JSON:
  `{type, title, labels, series}`) распознаётся и рисуется как SVG-график
  через `src/lib/chartRender.ts` (bar/line/pie, без внешних библиотек и
  сетевых запросов), а не выводится как текст.
- `src/lib/exportHtml.ts` — сборка печатной HTML-версии сообщения/чата для
  экспорта в PDF/PNG, включая шапку/подвал фирменного стиля проекта
  (`BrandKit`) поверх общего рендера markdown.
- `src/lib/promptBuilder.ts` — разбор ответа конструктора навыков.
- `src/components/` — интерфейс (сайдбар, проект, чат, навыки, настройки).

## Ограничения текущей версии

- Поиск по документам не «умный» (без embeddings/RAG) — весь текст
  документов проекта подставляется в системный промпт целиком, с лимитом по
  объёму. Для очень больших баз знаний это может упираться в лимит контекста
  модели.
- Синхронизация между несколькими компьютерами не реализована — папка
  `Личный чат` живёт на одном устройстве (можно вручную скопировать папку
  или держать её в Google Диске/Яндекс Диске/Dropbox и т.п. для резервной
  копии).
- Word правит текст, а не оформление: шрифты, отступы, стили абзацев и всё
  прочее оформление задаются в самом Word — приложение их сохраняет, но не
  меняет. Абзац со смешанным начертанием после правки становится однородным (см.
  раздел «Word»), а таблицы правятся только в Word. Сквозной сценарий проверен на
  настоящем `.docx` с заголовками, списком и таблицей: разбор на блоки, ручная
  правка, правка агентом (замена/вставка/удаление), сохранение и повторное
  открытие — файл после этого читается независимой библиотекой без единого
  предупреждения.
- Медиагенерация проверена end-to-end на подменённом (mock) API-ответе — сама
  структура запроса/опроса/скачивания соответствует официальной документации
  Polza.ai (`POST /v1/media`, `GET /v1/media/{id}`), но с реальным ключом и
  реальными моделями не тестировалась (нет доступа к внешним API в этой
  среде). Точные ID моделей и их параметры меняются на стороне Polza —
  сверяйтесь с polza.ai/models, если модель не найдена или вернула ошибку.
- GitHub-интеграция коммитит через Contents API (по файлу за раз, всегда в
  основную ветку репозитория) — это не полноценный Git: нет локальной
  истории, веток, merge, работы с большими бинарными файлами. Для реальной
  разработки это осознанно упрощённый режим быстрых точечных правок с
  ассистентом, а не замена `git`/Claude Code. Дерево репозитория и коммиты
  проверены сквозным сценарием на подменённом (mock) GitHub API — с реальным
  токеном не тестировалось (нет доступа к api.github.com из этой среды).
- Агент Excel строит таблицы и формулы, но не оформление: цвета, границы,
  ширину столбцов и объединение ячеек он не задаёт (только форматы чисел).
  Существующее оформление файла при этом не портится — оно сохраняется как есть.
- Графики строятся ассистентом текстом (JSON-блок), а не выбором из
  готового набора — если модель отдаст некорректный JSON, вместо графика
  покажется понятное сообщение об ошибке, а не пустое место.
- Чат-боты/воронки работают только пока приложение открыто (см. раздел
  выше) — это не круглосуточный хостинг ботов. Сквозной сценарий
  (подключение → срабатывание триггера по входящему сообщению → отправка
  шага воронки → ручной ответ) проверен на подменённом (mock) Telegram
  API; ВКонтакте и MAX используют тот же проверенный код опроса/отправки и
  формат запросов, восстановленный из официальной/сторонней документации,
  но отдельно с моками не прогонялись и с реальными токенами не
  тестировались (нет доступа к api.telegram.org/vk.com/botapi.max.ru
  из этой среды). Перед боевым использованием стоит внимательно проверить
  «Проверить» на каждой площадке и протестировать воронку на себе.
- Какой именно хост бот-API у MAX — из этой среды проверить нельзя (внешняя
  сеть недоступна), поэтому вместо одного «правильного» адреса приложение
  перебирает известные и подставляет сработавший, а поле «Адрес API» позволяет
  вписать свой. Перебор хостов и разбор ошибок проверены на подменённом
  (mock) `fetch`; разбор сетевых ошибок дополнительно проверен вживую —
  «Проверить» в собранном приложении корректно объясняет ошибку прокси
  человеческим языком вместо кода `net::ERR_*`.
- Веб-поиск по умолчанию работает через разбор HTML-страницы DuckDuckGo — это
  не официальный API, поэтому он может сломаться, если DuckDuckGo поменяет вёрстку,
  или начать отвечать пустотой при частых запросах. Разбор выдачи и чтение страниц
  проверены на сохранённых образцах реальной вёрстки (в среде сборки внешние сайты
  недоступны), с живым DuckDuckGo не тестировались. Если поиск подводит —
  переключитесь в Настройках на Tavily.
- Изображения из чата уходят модели как картинки только если выбранная модель
  умеет их «видеть». Видео и аудио не передаются моделям вообще (это ограничение
  текстовых моделей, а не приложения) — прикреплённый ролик виден ассистенту
  только как имя файла, размер и путь.
- ИИ-боты отвечают, пока приложение открыто и площадка запущена — как и воронки.
  Сквозной сценарий (входящее сообщение → системный промпт проекта → ответ модели
  → отправка → память переписки) проверен на подменённом API площадки и модели;
  с реальным токеном MAX/Telegram/VK не тестировался (эти хосты недоступны из
  среды сборки). Перед боевым использованием обязательно напишите боту сами и
  проверьте, что он отвечает по делу и не выдумывает условия.
- «Excel» умеет значения и формулы, но не всё, что умеет Excel: сводные таблицы,
  макросы, диаграммы и условное форматирование не редактируются (при сохранении
  они не теряются — файл перезаписывается через исходную книгу, — но управлять
  ими из приложения нельзя). Пересчёт покрывает ~290 функций библиотеки плюс
  реализованные нами; если встретится нереализованная, ячейка покажет
  `#NAME? (ИМЯФУНКЦИИ)` — по этому имени сразу понятно, чего не хватает.
- Облако проверено сквозным сценарием (подключение → список папок → скачивание,
  в том числе экспорт Google-документа → загрузка обратно) на подменённых API
  Яндекса и Google; с реальными токенами не тестировалось — внешние хосты
  недоступны из среды сборки. Токен Google из OAuth Playground живёт около часа,
  после чего его нужно получить заново.
- Запуск сборки через Actions проверен на подменённом GitHub API (отправка
  запроса на нужный workflow и ветку, опрос статуса); с реальным токеном не
  тестировался.
- Автопостинг в соцсети (публикация постов, а не переписка ботом) — по
  вашему решению не делаем.
- Задачи по времени работают только пока приложение открыто (тот же принцип,
  что и у чат-ботов/воронок выше) — это не облачный планировщик, а проверка
  внутри самого приложения раз в 30 секунд. Если задача пропущена (приложение
  было закрыто в момент срабатывания), она выполнится при следующем запуске,
  как только приложение это обнаружит. UI-сценарий (создание/включение-
  выключение/удаление задачи, расчёт следующего срабатывания для разовых/
  ежедневных/еженедельных задач) проверен сквозным Electron-тестом; реальный
  вызов модели по расписанию не тестировался (нет доступа к api Polza из
  этой среды).
