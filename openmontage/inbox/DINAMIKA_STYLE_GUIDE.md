# Агентство Динамика — гайд по монтажу talking-head видео

Это накопленные правила и техническая методика по итогам первого видео
(SMM / «Собственнику хочется повысить доход»). **Прочитай этот файл целиком,
прежде чем начинать новое видео с новым текстом.**

Важно: всё под `openmontage/projects/**` в `.gitignore` и НЕ переживает
пересоздание контейнера — HTML-сцены, рендеры, финальные версии придётся
собирать заново с нуля каждый раз. Этот файл (в `inbox/`) — единственное,
что реально сохраняется между сессиями, поэтому в нём лежит вся рабочая
методика и куски кода, чтобы не изобретать заново.

## 1. Бренд-константы

- Цвета: `#FF2F6D` (неоновый розовый), `#00D9FF` (электрик циан),
  `#0A0A0A` (чёрный), `#FFFFFF` (белый).
- Шрифт: «Dinamika» — угловатый, с полной кириллицей. Файл лежит и
  реально закоммичен в **корне репозитория**: `/DINAMIKA-extended.woff2`
  (`.ttf`/`.woff` тоже там) — единственная надёжная копия, брать оттуда,
  копировать в `fonts/` каждой новой HTML-сцены.
- Визуальный язык: градиент magenta→cyan, чёрно-розово-циановые угловатые
  «плашки» (pills) с жирным капслочным текстом шрифтом Dinamika,
  halftone-точечная текстура, поп-арт 4-лучевые искры-звёздочки, дуотон-кольца
  на аватарках (`conic-gradient(from 0deg, #ff2f6d, #00d9ff, #ff2f6d)`).
- Логотип и реальные бренд-ассеты (лого, штамп-SVG, мокапы постов) — в
  `openmontage/inbox/ДИНАМИК НОВЫЙ САЙТ.zip` (закоммичен, значит
  переживает пересоздание контейнера) плюс отдельный `inbox/Frame 160.svg`.
  Распаковать заново (`unzip` во временную папку, например
  `inbox/_extracted/` — она сама не коммитится) и использовать как референс
  цвета/шрифта/лого, не как декор впрямую, если не попросят иначе.

## 2. Структура видео — САМОЕ ВАЖНОЕ

Видео **не** идёт непрерывно с плашкой поверх. Оно чередует:

- **Живые куски** — оригинальное видео говорящей головы, поверх которого
  плавают прозрачные текстовые плашки (без фона на весь экран).
- **Полноэкранные моушн-вставки** — видео полностью скрыто, на экране только
  графика (дуотон-фон, инфографика и т.п.), но **аудио оригинальной записи
  продолжает звучать** непрерывно.

Не возвращайся к первой версии (плашка-полоса сверху весь ролик) — это было
явно отвергнуто пользователем.

Порядок сцен в первом видео (для образца структуры, не текста):
1. Живое видео + 3 плашки внахлёст сверху (первый тезис).
2. Полноэкранная моушн-вставка (дуотон + вертикальный таймлайн шагов), видео
   скрыто, звук продолжается.
3. Живое видео + 3 плашки (второй тезис/возражение).
4. (Опционально, зависит от текста) полноэкранная вставка-контраст.
5. Круглая аватарка с дуотон-кольцом + расширяющаяся сетевая инфографика
   (хаб + узлы-спутники), видео идёт как маленький кружок, звук родной.
6. Аутро — использовать существующий `outro_final.mp4`/`outro-sting`
   проект как есть, если пользователь не просит менять.

## 3. Плашки (pill) — рабочий HTML/CSS паттерн

Каждая фраза = **отдельная плашка**, не объединять несколько строк в одну.
Плашки идут по одной, каскадом (то слева, то справа), с overshoot-анимацией.

Проверенный код (`scene1/index.html`, аналогично `scene_regret/index.html`):

```html
<style>
  .card {
    position: absolute; top: 130px; left: 0; right: 0;
    display: flex; flex-direction: column; align-items: flex-start;
    gap: 14px; padding-left: 70px;
  }
  .pill {
    font-family: "Dinamika", sans-serif; font-weight: 700;
    font-size: 82px; letter-spacing: 1px; text-transform: uppercase;
    padding: 16px 40px; opacity: 0;
    animation-duration: 480ms;
    animation-timing-function: cubic-bezier(0.34, 1.5, 0.4, 1);
    animation-fill-mode: both;
  }
  .p1 { background:#0a0a0a; color:#fff; animation-name: slide-left; animation-delay: 150ms; }
  .p2 { background:#ff2f6d; color:#fff; margin-left:60px; animation-name: slide-right; animation-delay: 500ms; }
  .p3 { background:#00d9ff; color:#0a0a0a; animation-name: slide-left; animation-delay: 850ms; }
  @keyframes slide-left  { from{opacity:0; transform:translateX(-60px);} to{opacity:1; transform:translateX(0);} }
  @keyframes slide-right { from{opacity:0; transform:translateX(60px);}  to{opacity:1; transform:translateX(0);} }
</style>
<!-- ВАЖНО: на .card НЕТ класса .clip — см. п.6 про баг с inset:0 -->
```

## 4. Круглая аватарка (avatar-ring)

HTML-сторона (`scene3/index.html`):

```html
<div class="avatar-ring"><div class="avatar-hole"></div></div>
```
```css
.avatar-ring {
  width: 340px; height: 340px; border-radius: 50%;
  background: conic-gradient(from 0deg, #ff2f6d, #00d9ff, #ff2f6d);
  padding: 10px;
}
.avatar-hole { width:100%; height:100%; border-radius:50%; background:#fff; }
```
`.avatar-hole` — просто «дырка» под композитинг, реальное видео туда
вклеивается через ffmpeg (ниже), не рендерится в HyperFrames.

**Маска (обязательно антиалиасинг, иначе «квадратные углы» за кругом):**

```python
# генерируется один раз через PIL, 4x supersample + LANCZOS downscale
from PIL import Image, ImageDraw
size = 320
scale = 4
big = Image.new("L", (size*scale, size*scale), 0)
d = ImageDraw.Draw(big)
d.ellipse((0, 0, size*scale, size*scale), fill=255)
mask = big.resize((size, size), Image.LANCZOS)
# положить mask в альфа-канал RGBA png circle_mask_aa.png
```

**Кадрирование лица + центрирование носа** — методика, а не готовые числа
(координаты будут другие в новом видео!):

1. Взять кадр из живого видео (`ffmpeg -ss <t> -i clip.mp4 -frames:v 1 frame.png`).
2. Наложить сетку линий через PIL (`ImageDraw.line`) с подписанными
   координатами, найти пиксельные `(x_nose, y_nose)` кончика носа.
3. Выбрать размер квадратного кропа `w=h` (одна и та же величина и для
   ширины и высоты, чтобы не исказить пропорции) — например `950` px даёт
   умеренный зум для кадра 1080×1920; можно взять больше/меньше по запросу
   «побольше/поменьше».
4. `x_start = x_nose - w/2`, `y_start = y_nose - w/2` (клэмпить в границы
   исходного кадра).
5. Проверить результат наложением перекрестия по центру (`160,160` для
   финальных 320×320) и подкорректировать на глаз перед финальным рендером.
6. Финальная композиция:

```bash
ffmpeg -y -i face_clip.mp4 -i circle_mask_aa.png -filter_complex \
  "[0:v]crop=W:H:X:Y,scale=320:320[v];[v][1:v]alphamerge[circ]" \
  -map "[circ]" -c:v qtrle avatar_circle.mov

ffmpeg -y -i scene3_graphics.mp4 -i avatar_circle.mov -i face_clip.mp4 \
  -filter_complex "[0:v][1:v]overlay=x=380:y=70:format=auto[v]" \
  -map "[v]" -map "2:a" -c:v libx264 -crf 18 -preset veryfast -c:a aac -b:a 192k \
  seg_avatar.mp4
```

## 5. Сетевая инфографика (хаб + узлы)

- Хаб = **полное название концепции** («Интегрированные маркетинговые
  коммуникации»), НЕ аббревиатура.
- Аббревиатура/ключевой канал (например «SMM») — один из равных узлов
  вокруг хаба, визуально выделен акцентным цветом (`background:#ff2f6d`
  вместо чёрного), но по размеру и оформлению — такой же круг, как остальные.
- Узлы — чёрные круги 180×180px, линии от хаба — `linear-gradient(90deg,
  #ff2f6d, #00d9ff)`, угол/длина считаются через `math.atan2`/`math.hypot`
  под конкретные координаты хаба и узлов.
- Раскладка: верхний ряд из части узлов, нижние ряды — оставшиеся, с
  выделенным узлом ближе к центру/по центру нижнего ряда.

## 6. Технические грабли HyperFrames/ffmpeg (уже наступили — не повторять)

- **`--workers=2` обязательно** при рендере (`npx hyperframes render . -o out
  --fps=30 --workers=2 [--format=mov]`). При автоопределении воркеров в 1
  включается `useStreamingEncode` с багом масштабирования (контент выходит
  уменьшенным/с чёрными полями).
- **Не совмещать `class="clip"` (даёт `position:absolute; inset:0`) с
  собственными `top/left/right/bottom`** на одном элементе — незаданные
  стороны наследуют `inset:0` и элемент растягивается на весь экран. Если
  нужна кастомная позиция — просто не вешать `.clip`, видимость по времени
  всё равно работает через `data-start`/`data-duration`.
- Прозрачные оверлеи — рендерить с `--format=mov` (alpha channel), не mp4.
- `anullsrc` для тишины — **всегда** с явным `-t <duration>`, иначе
  бесконечный источник даёт runaway-рендер и «No space left on device».
- Склейка разнородных сегментов — через `concat` **фильтр** (не demuxer), с
  `setsar=1` на каждом видео-входе перед конкатом.
- Если нет доступа к STT (huggingface.co обычно заблокирован в песочнице) —
  попроси у пользователя точный текст и раскладку по репликам, а границы
  слов/фраз ищи через `ffmpeg -af silencedetect` на нескольких порогах
  (-20/-25/-35/-40 dB), сверяя с длительностью клипов и числом слов.
  Обязательно подтверди у пользователя тайминг перед рендером.
- Remotion в этой песочнице: браузер — `/opt/pw-browsers/chromium_headless_shell-*/chrome-linux/headless_shell`
  (обычный `chromium` не работает — "Old Headless mode removed"),
  `--ignore-certificate-errors` для Google Fonts (TLS-прокси песочницы).

## 7. Процесс работы с пользователем

- Пользователь пишет по-русски, разговорным стилем, часто с опечатками —
  внимательно вычленять конкретные технические правки из потока речи.
- Присланные референс-скриншоты/коллажи **не сохраняются на диск** и
  теряются при сжатии контекста между сессиями — если правка касается
  точного визуального соответствия референсу, а сам референс не виден в
  текущем контексте, лучше явно попросить прислать его заново, чем гадать
  третий раз подряд.
- После каждой правки — рендерить, делать фрейм-грэб именно той части кадра,
  которая менялась (при необходимости с зумом через PIL и разметкой сетки/
  перекрестия для проверки центровки), и только потом отправлять файл
  пользователю через `SendUserFile` с кратким описанием, что именно
  изменилось, на русском.
- Не трогать то, что не просили менять (например аутро с искрой — оставлять
  как есть, если явно не попросят иначе).

## 8. Что нужно сделать заново, когда придёт новое видео

Так как `projects/` не сохраняется — при новом видео:
1. Скопировать `/DINAMIKA-extended.woff2` (корень репозитория) в `fonts/`
   каждой новой HTML-сцены, воссоздать структуру проекта заново.
2. Пересобрать HTML-сцены по шаблонам из этого файла (разделы 3–5),
   подставив новый текст/новые тезисы.
3. Заново подобрать тайминг реплик (раздел 6, silencedetect).
4. Заново подобрать кроп аватарки под конкретный новый ракурс лица
   (раздел 4, методика с сеткой и центровкой носа) — координаты будут
   другие.
5. Спросить, актуален ли ещё открытый вопрос по стилю плашек (раздел 3),
   и если да — попросить референс заново.
